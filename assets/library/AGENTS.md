# キャラクター素材を扱うAIへの指示

このディレクトリの素材は [README.md](README.md) と、リポジトリルートの `catalogs/character-library-v1.json` を入口に利用する。

並行生成・登録・整理は [画像管理仕様](../../docs/IMAGE-ASSET-MANAGEMENT.md) に従う。開始前に `catalogs/character-asset-management-v1.json` の担当予約を確認し、生成担当は専用バッチだけへ書き込む。管理在庫は `catalogs/character-asset-registry-v1.json`、人が見る入口は [管理一覧](character-assets.html)。生成中の予約範囲は確定在庫へ混ぜず、既に在庫登録された原本を予約で隠さない。

- まず台帳が指定する採用版を読む。`v*` の最大値、最終更新時刻、`generation-candidates/` の画像から採用版を推測しない。
- 汎用ポーズは台帳の `key_poses`・`expanded_key_poses`・`eyecatch_key_poses` から選ぶ。追加分は `expanded/<pose>`・`eyecatch/<pose>` で明示指定し、既存ポーズを置き換えない。collectionと素材構成の一覧は [README.md](README.md) を参照し、収録だけで完成動画の採用先や `active_production_set_ids` を変更しない。
- 通常姿・生成シート・切り出しPNG・正確な生成条件・入力の役割とSHA・登録座標・確認記録を [画像管理仕様](../../docs/IMAGE-ASSET-MANAGEMENT.md) に沿って保全する。既存原画を上書きせず、派生や修正は新しい版に保存する。
- 顔、眼の形式、種固有の模様、色、水彩の質感を採用通常姿へ合わせる。新しいポーズはその動物自身の通常姿を同一性の参照にする。全員の線を機械的に同じpx値へ増減しない。
- 描画時は登録済みの身体基準高と足元支点を使う。同じ動物の同じ校正済み生成シートの全動作へ共通の等方縮尺を適用し、屈伸・ついばみ姿勢を個別のbbox高で拡大しない。複数シートの追加素材は各frameの `reference_height_px` とシート間の校正記録を使う。空中姿勢の地面推定を足の実接触の測定と取り違えない。
- オナガドリは身体で縮尺を決め、長い尾の範囲を別に確保する。尾幅による全体fit、尾末端の足支点化、羽先の切り落としを行わない。
- `peck_half` / `peck_down` は下向きの仕草として扱い、くちばしと地面の接触が確認済みとは記述しない。
- GIFは登録済みキーポーズの確認用。滑らかな補間、音声同期、画面内の余白、動作の頻度は実際のエピソードで確認する。紅茶はカップを持つループなので、カップの登場・退場もシーン側で確認する。
- 透過RGBAを保持する。アルファ最大254やアルファ0内のRGBだけを理由に不良と判定せず、明色・暗色への正しい合成で確認する。輪郭の膨張・収縮、色抜き、アルファ清掃を既存原画へ適用しない。
- 実利用のパスは台帳と登録情報の相対パスで解決する。C/Dドライブの履歴パス、元生成先、DtempのQA先が現環境に存在することを前提にしない。過去の実行入力JSONは履歴として読み、再登録するときは現PCの実入力から新しい設定を作る。
- 別環境ではGit LFSの実体を取得し、`python tools/character_library.py verify` を実行する。検証エラーを隠すためのハッシュ書換えはせず、参照元・採用先・ファイル実体を確認して原因を直す。
- 更新は依頼の範囲で進める。無関係の進行中制作、既存の採用動画、他キャラクターの原画を変更しない。このファイルによる追加の承認フローは設けない。
