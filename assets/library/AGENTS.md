# 素材ライブラリを扱うAIへの指示

全120種類の入口は [利用案内](README.md) と `catalogs/asset-library-current-v1.json`。素材台帳から各IDの `assets/library/characters/<id>/current/asset.json` を辿り、画像・ポーズ・動作を同じ手順で扱う。

生成・比較・採用は [画像管理仕様](../../docs/IMAGE-ASSET-MANAGEMENT.md)、配置の測定は [配置仕様](../../docs/LAYOUT-ALIGNMENT.md) を正本とする。GitHubの収録・同期は [公開仕様](https://github.com/anoneunknowns/youtube/blob/main/docs/GITHUB-PUBLICATION.md) を参照する。

## 案内の更新方針

- 利用者向けガイドを「新規」「既存」「追加分」等の収録時期で分割しない。常に全IDを一つの素材一覧と共通の `current/` 台帳で案内し、用途・機能で説明する。
- ID、収録素材数、ポーズ・動作の有無、リンク、実体は、更新時に実台帳・各 `asset.json`・`clips.json` から確認する。表示数を固定の思い込みで引き継がない。
- 名前空間 `basic/`・`expanded/`・`eyecatch/`・`gimmick/`・`app/` は機能を識別する互換IDとして保持する。日本語説明は基本の表情・全身動作・短い演出・植物や物体等の動作・操作への反応として記述し、名称から制作時期や優先順位を推定しない。

## 画像を利用する場合

- 静止画利用の第一導線は、選択したIDの `current/neutral.png`。画像表示にPython、動画ツール、全ZIPの導入を要求しない。必要な `asset.json` のID・SHA・取得元・登録と利用条件を取込記録へ添える。
- `current/neutral.png` は採用領域の単独PNGとして用意されている。シート全体を通常姿と誤認せず、`current/` のPNGを再度切り出さない。
- `neutral.path`・`poses[キー].path`・`clips.path` は `asset.json` のある `current/` から解決する。`source_path`・`source_index.path`・`source_registrations[].path` はプロジェクトルートを基準とする。利用PNGのSHAと元シートの `source_sha256` を混同しない。
- Git LFSのポインタを画像本体と扱わない。画像・JSONを同じ参照から取得し、必要に応じて対応する `sha256` と実体を照合する。通常PNGだけ取得した状態に、ポーズ等を要求する全体検証を課さない。
- 利用できるポーズは各 `asset.json` の `poses` から選ぶ。動作の `frames` はそのキーへ対応付け、時間・ループ・移動・再生効果を読む。時間未指定の動作は利用場面で設計・確認する。`character_library.py` へ `basic/` 相当のポーズを渡す場合だけ接頭辞を除く。
- `scene_relative_scale` は場面の身体高比で、PNGの登録基準高とは別。頭部アイコンは `icons` から取得し、全身ポーズの身体尺度を与えない。座位からの反応は座位用ポーズの有無を確認する。
- 登録された支点と校正済みシートごとの共通基準を使う。足元・基部・胴体中心を区別し、しゃがみ、翼の開閉、尾、炎、ローターの位相、虹の部分表示ごとに外接矩形で拡大しない。空中姿勢の推定地面と実接触を取り違えず、原画の浮きを二重に加えない。
- オナガドリは身体で縮尺を決め、尾の全幅を収める。`peck_half`・`peck_down` は下向きのしぐさとして扱い、くちばしの地面接触を保証しない。紅茶のループはカップを持つ姿勢なので、通常姿との接続で出入りを設計する。
- 透過RGBAと原画の色・輪郭・質感を保持する。アルファ最大254やアルファ0内のRGBだけで不良とせず、明色・暗色へ正しく合成して確認する。輪郭の膨張・収縮、色抜き、アルファ清掃を原画へ適用しない。
- ファイル整合、画風・同一性、素材GIF、完成作品の動作検査を区別する。最大表示、両軸配置、切れ、体格・支点の跳ね、ループ、教材や字幕との余白は実際の利用画面で確認し、過去QAを現在の合格内容へ書き換えない。

## リメイク案のユーザー比較

- リメイク前に修正すべき具体的な欠点と改善条件を決め、対象の新規案を作る。既存の原画・登録・SHAは固定して保全し、同尺度の明暗背景・原寸表示・前後ポーズとのつながりで比較する。
- 改善が明確で、同一性・画風・体格・支点・動作・精細さ等に退行がないときだけ差し替える。同程度・判断不明・悪化なら既存を維持し、新旧SHAと比較条件・判定根拠を記録する。
- 良好な姿勢は残し、必要な姿勢だけを採用通常姿からの新規描画等で比較する。形の崩れと演技の軸・深まりの不足を分け、眼・帽子・顔の投影差を別個体化と取り違えない。
- 画像のリメイクでは [比較・選択の手順](../../docs/IMAGE-ASSET-MANAGEMENT.md#リメイク候補をユーザーに提示する) と `tools/image_remake_review.py` を使い、前バージョンと候補を同じ画面へ提示する。
- 前バージョンとAIおすすめは設定で明示し、選択前から文字付きの印を出す。初期選択を自動でおすすめにせず、候補のどれかを前バージョンと偽って表示しない。
- 画像のSHA、各案の校正済み基準高・支点、同尺度の表示を確認する。ユーザーが選んだ結果は比較設定の `decisions/` と `show` コマンドで読み、推測で補わない。
- 比較の画像パスは固定した原画または無改変snapshotへ結び付ける。採用時に変わる `current/` のコピーだけを参照せず、正式適用後も前バージョンを同じSHAで読めるようにする。
- 選択履歴と実際の素材への適用を区別する。適用する場合は選択されたSHAに対応する登録・動作・品質確認を揃え、良好な原画と過去の採用を保全する。
- ユーザーから委任された採否は指示と確認結果へ結び付け、ユーザー自身のクリックと分けて記録する。検証用の選択を実際のユーザー履歴へ混ぜない。

## 生成・登録・管理する場合

- 動物を増やすときは、シャム猫・ハリネズミ・トラの軽い擬人化か、ヤイロチョウの丸く簡略化した小物のパターンに合わせる。ハムスターと黄色い小鳥は例外で、新しい動物の標準に流用しない。擬人化キャラを自然な四足姿のまま合格にせず、小物も細密な図鑑調へ寄せない。採用原画SHAへ `style_pattern`・用途・現在の画風確認を結び付け、旧QAを現在の合格へ書き換えない。


- [画像管理仕様](../../docs/IMAGE-ASSET-MANAGEMENT.md) と `catalogs/character-asset-management-v1.json` の担当予約を先に確認する。担当専用バッチだけへ書き、他担当の生成中領域を移動・削除・上書きしない。管理在庫の更新は管理担当が直列に実施する。
- 顔、眼、模様、色、輪郭、水彩の質感は、対象素材の採用通常姿を基準にする。画風だけの参照と、同一性の参照・編集対象・合成要素を区別し、動物の顔や帽子を物体へ転写しない。
- 原画・生成シート・無損失切り出し・正確なプロンプト・入力の役割とSHA・出力・座標・確認記録を保全する。元原画を上書きせず、修正は別の版へ保存して採用先を明示する。失われた条件や担当を推測で補わない。
- `current/` は採用台帳から作る参照用コピー／無損失切り出し。採用管理担当は `unified_asset_library.py build` と `verify` で更新・確認する。利用側は画像や期待ハッシュを手編集せず、不一致の原因を取得漏れ・参照元・実体から調べる。
- 通常姿・短い演出の明示採用は `catalogs/character-adoptions-v1.json` を確認する。選択の根拠とSHAに結び付けた採用記録を優先し、過去の画風QAやcollectionを書き換えて現行版を選ばない。`current/` の切替では直前の画像と登録を保全し、身体基準・全ポーズ・clip・共通台帳を揃える。
- 部分採用では変更しない元パス・SHA・登録・clipを保持し、必要な既存の選択根拠へ新しい根拠を追加する。公開前には画像・文書とも公開側の台帳と収録実体へ照合する。
- 更新は依頼された範囲に限定する。素材の収録だけで作品の採用先や `active_production_set_ids` を変更しない。無関係の制作や原画を変更せず、このファイルによる追加の承認手順は設けない。

## 保存範囲

制作原本には候補・過去資料・ローカル動画も保管する。GitHub公開と公開用checkoutから配布する素材ZIPの収録は、同checkoutの `catalogs/github-publication-v1.json` の `files`・`character_library_files` を正本とする。profileのない制作原本からのexportは、そのcheckoutのローカル在庫を収録するため配布用とは区別する。履歴のパス・SHAは配布を保証しない。制作原本の全保管検査と、画像利用・公開範囲の検査を区別し、画像だけの利用に未取得の動画や全履歴を要求しない。
