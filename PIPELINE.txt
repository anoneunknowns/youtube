  8分以上9分未満。チャンネルバナーの制作とは別の構成。
  現行の制作セット：counting-garden-blue-sky-production-v002。
  冒頭は効果音なし。BGMなし、効果音は10種類を計33回。
  完成品・字幕・チャプター・技術検査：output/counting-garden-001-bright-v002/。
  採用素材一覧：catalogs/library-v1.json。
  採用仕様：design/counting-video-v1/production-spec-v2.txt。
  効果音・演技脚本：design/counting-video-v1/sound-cue-script-v2.txt。
  全発話本文と演出：design/counting-video-v1/cue-sheet-v2.json。
  音声準備表：design/counting-video-v1/audio-preparation-v5.json。

  Node：D:/Program Files/nodejs/node.exe、Python：C:/Python315/python.exe。
  FFmpeg：D:/dev/FFmpeg/ffmpeg-9.0.2-essentials_build/bin/。
  FFmpegはGyan Essentialsの配布ZIPからD:/dev/FFmpegへ導入し、OSのユーザーPATHに登録した。
  プロジェクト専用のランタイム複製・恒久PATH追加は行わない。
  共通PowerShell内ではOS登録のMachine/User PATHを優先して引き継ぐ。
  作業ディレクトリはD:/codex_projects/youtube、一時保存はD:/temp。
  NodeキャッシュはD:/dev/caches/npm、モデルはD:/dev/caches/huggingface。
  package-lock.jsonでkokoro-jsとTransformers.jsの採用版を固定する。
  モデルが未配置ならtools/prepare_speech_model.ps1とtools/prepare_phoneme_model.ps1で取得・hash検証する。

採用音声の再利用
  assets/library/audio/speech/kokoro-af-heart/v002/measurements.json を直接参照する。
  clips/に数300本・セリフ11本を保存し、相対path・実測長・SHA-256を記録した。
  voiceはen-US af_heart、Kokoro fp32、生成速度0.98。Apache-2.0、関連ライセンスを同梱。
  speech-acceptance.jsonがaccepted:trueかつ現音声・manifest・根拠のhashが一致することが必須。
  generate_speech.mjsも同じmodel/voice/speed/dtypeならこの検査済み音声を優先する。
  rejected-source-hashes.jsonの旧takeはキャッシュ再利用時・新規生成直後とも拒否する。
  数字音声を再生成しないため、同じ発音不備を毎回作り直すことを防ぐ。
  英語字幕・表示数字・演出は同一timelineから出力する。

制作コマンド例
  以下は未存在の新しい出力フォルダに対して実行する。既存完成品への上書きは拒否する。
  $episodeOut = 'output/new-counting-video'
  $speech = 'assets/library/audio/speech/kokoro-af-heart/v002/measurements.json'
  $acceptance = 'assets/library/audio/speech/kokoro-af-heart/v002/speech-acceptance.json'

  python tools/video_pipeline.py validate --episode episodes/counting-garden-001.json --cues design/counting-video-v1/cue-sheet-v2.json
  python tools/video_pipeline.py plan --episode episodes/counting-garden-001.json --cues design/counting-video-v1/cue-sheet-v2.json --speech-manifest $speech --out "$episodeOut/timeline.json"
  python tools/build_audio_mix.py mix --timeline "$episodeOut/timeline.json" --speech-manifest $speech --speech-acceptance $acceptance --sfx-dir assets/library/audio/sfx/garden/v001 --out "$episodeOut/master.wav" --work-dir D:/temp/youtube-audio
  python tools/render_counting_video.py --timeline "$episodeOut/timeline.json" --audio "$episodeOut/master.wav" --theme design/counting-video-v1/themes/bright-garden-v002.json --output "$episodeOut/paspla-studio-count-1-to-300-blue-sky-1080p.mp4" --preset veryfast --crf 18
  python tools/export_delivery_metadata.py --timeline "$episodeOut/timeline.json" --output-dir $episodeOut --video-filename paspla-studio-count-1-to-300-blue-sky-1080p.mp4

新しい音声が必要な場合
  未検査の生成候補はD:/tempに置き、採用音声フォルダへ直接上書きしない。
  tools/generate_speech_candidates.mjs --jobs <JSON配列> --out <新しい候補フォルダ> で自然な文脈を生成できる。
  jobsの各行はidとtext、またはidとphonemes。生成条件とsourcehashを記録する。
  必要な語は音響・音素の確認後、tools/extract_reviewed_word.pyで切り出す。
  CTCの時刻だけで切らず、前後語の混入と最終子音の切断がないことを波形でも確認する。
  切り出し後の単独音声を必ず再検査する。
  採用候補一式はtools/register_speech_library.mjsで新しいlibrary版へ登録できる。
  登録は発音の承認を意味しない。新しいmanifestに対する全件検査と採用ゲートが必要。

音声の検査と採用ゲート
  node tools/verify_speech.mjs --manifest <新manifest> --out <新isolated-asr.json>
  node tools/verify_phonemes.mjs --manifest <新manifest> --out <新isolated-phonemes.json>
  python tools/verify_terminal_tails.py --manifest <新manifest> --out <新terminal-tail-review.json>
  単独音声認識は正解本文・前後の数をpromptへ与えずに実施する。
  独立音素認識で余分母音、欠落、異なる子音、反復を確認する。
  終端スクリーニングの疑い0件だけで全発音を合格にしない。
  数の意味が文脈中で正しく認識されても、元の単独音声警告は保持する。
  不一致はモデルの誤認の可能性も含め独立に検討し、未解決のまま採用しない。
  pronunciation-review.jsonに各音声hash、判断、独立根拠ファイルhashと具体的理由を記録する。
  node tools/review_speech_acceptance.mjs --manifest <新manifest> --asr <新isolated-asr.json> --pronunciation <新pronunciation-review.json> --out <新speech-acceptance.json>
  全件の網羅、音声hash、根拠hash、判断を照合し、古いクリップのレビュー流用を拒否する。
  build_audio_mix.pyも--speech-acceptanceを要求し、検査後に素材や根拠が変われば停止する。
  自動検査の一致は完全な発音保証ではない。人が全件試聴したと記録しない。

映像の最終検査
  python tools/verify_video.py --video <MP4> --timeline <timeline.json> --output-dir <未使用QA出力先>
  python tools/verify_layout.py --video <MP4> --timeline <timeline.json> --theme design/counting-video-v1/themes/bright-garden-v002.json --out-dir <未使用layout-QAフォルダ>
  python tools/video_contact_sheet.py --video <MP4> --timeline <timeline.json> --output-dir <未使用visual-QAフォルダ>
  全編decode、frame数・尺・1080p30fps・codec・BT.709・AAC・最終LUFS/true peakを検査する。
  frame数は切上げて音声の終端を覆い、最後のサンプルを切らない。
  decoded映像の範囲札と1/6/10/100/128/300を実測し、中央からのずれを1px以内とする。
  実際の導入、通常演出、開花、100のお祝い、200の休憩、300とフェードを画像で確認する。
  python -B -m unittest discover -s tests -q
  node tools/verify_speech.mjs --self-test
  node tools/review_speech_acceptance.mjs --self-test

管理
  旧版・不採用画像・比較用出力・作業キャッシュは最新検査後に削除する。
  最新で使う元PNG・登録・フォント・利用条件・生成元は再編集と再利用のため保持する。
  素材単位のv001は、その素材の現行採用版である場合がある。
  バナー・アイコン・サムネイルはbranding/paspla-studio/v001の現行一式を使う。
  関連するfour-operations／four-operations-2／four-operations-commonの修正は、ユーザーが明示した輪郭統一の範囲で行う。ユーザーのmaterials/はこの整理の対象外。
  validate/plan/prepare-audioのproduction_ready:falseは計画ツールの属性であり、完成判定はproduction-runと最終QAで行う。
