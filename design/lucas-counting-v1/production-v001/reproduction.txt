3. 字幕・章・タイトル・概要を動画と同じ新規フォルダへ保存

.venv/bin/python - <<'PY'
from pathlib import Path
import shutil
source = Path('output/lucas-counting-001-v001/audio-build')
dest = Path('output/lucas-reproduction-new/render')
for name in ['subtitles.srt', 'english-captions.srt', 'chapters.txt', 'youtube-title.txt', 'youtube-description.txt', 'upload-details.txt']:
    target = dest / name
    if target.exists():
        raise FileExistsError(target)
    shutil.copy2(source / name, target)
    assert (source / name).read_bytes() == target.read_bytes()
PY

  元の台詞・時刻を維持する再出力の手順。
  新しいtimelineへ変えた場合は対応するbuilderで納品テキストも作り直す。
  旧テキストを内容/時刻の異なる動画へコピーしない。

  全41値/39式、字形と各桁、全38受渡し、19→20の表示移行、実個数/carry/履歴、

5. 新しい最終AACの認識継承可否を判定

.venv/bin/python design/lucas-counting-v1/production-v001/audio/bind_final_aac.py --video output/lucas-reproduction-new/render/paspla-studio-lucas-numbers-L0-to-L40-1080p.mp4 --out output/lucas-reproduction-new/final-video-binding.json

  未使用の--outファイルを使う。採用事前AACは
  output/lucas-counting-001-v001/audio-build/aac-preflight-v001.m4a、採用ゲートは
  output/lucas-counting-001-v001/speech/aac-preflight-v001/preflight-acceptance.json。
  全パケットの内容/サイズ/PTS/DTS/duration/priming、stream条件、デコード後の
  左右PCMが完全一致した場合だけ、全104cueの事前AAC認識・語頭末確認を継承できる。
  新しい対象動画に対するbindingが必要で、full-v002の既存bindingだけを流用しない。
  不一致の場合は新AACの新規ASR/CTC、語頭/語末、音量/true peak、左右音声、
  予定外の音や無音、同期を監査して新しい採否を残す。
  波形一致検査やbindingを、新たな認識または人による全編試聴と記録しない。
  同じ入力でもFFmpeg等の版で動画bytes/SHAやAACが変わり得るため、
  SHAの一致だけで新動画の表示・時刻・音声を検査済みにはしない。

任意：採用PCM群からmaster/timelineを再構築する場合
  通常の再出力では不要。モデルからTTSを生成し直す工程とも区別する。
  固定の個別採用音源・ゲート・CTCを明示する。今回はcodec-corrections未使用。

.venv/bin/python tools/build_lucas_episode.py --speech-manifest output/lucas-counting-001-v001/speech/measurements-selected-v003.json --speech-gate output/lucas-counting-001-v001/speech/speech-acceptance.json --phonemes output/lucas-counting-001-v001/speech/isolated-phonemes-selected-v003.json --ffmpeg .venv/bin/ffmpeg --out-dir output/lucas-rebuild-new

  新masterを描画するなら、rendererが読むパスも新masterへ明示する。
  builderのmaster_audio.pathだけを変更してもrendererの入力は切り替わらない。
  元timelineを上書きせず、描画用の派生JSONを作る例：

.venv/bin/python - <<'PY'
from pathlib import Path
import json
source = Path('output/lucas-rebuild-new/timeline.json')
plan = json.loads(source.read_text())
plan['master_path'] = 'output/lucas-rebuild-new/master.wav'
with source.with_name('timeline-render.json').open('x', encoding='utf-8') as stream:
    json.dump(plan, stream, ensure_ascii=False, indent=2)
    stream.write('\n')
PY

  このtimeline-render.jsonと未使用のrender先で再描画し、検査の--timeline/--masterも
  それぞれ新しいものへそろえる。新しい字幕等はlucas-rebuild-newから使う。
  新master/AACの採否を新出力へ束ね直し、元の合格を無条件には継承しない。

履歴・演出・保存
  full-v001は経路/案内線等による字形上書きの不採用履歴として保全。
  render-v001の凍結コード、修正前native/実MP4、負の対照、旧QAも残す。
  full-v002は経路と全カード背景を字形より先に描画し、種の添字案内線を数値外へ回す。
  最終合成後、元字形alpha>=128の実画素が描画直後のRGBを保つ検査を追加した。
  同じ表示尺度の通常カウント/受渡しでactorの位置/身体高を維持する。
  演出の判断はrenderer/acting-long-interval-review.json/.txtを参照。
  本作の静かな観察と25演技窓を採用し、現行Fibonacci v004の細かな視線追従/頷きと
  同じ応答性を達成したとは記録しない。窓数や静止秒数を一律条件にしない。
  今回の自動全編解析、原寸/動作抜粋の確認、新規認識と同一AACによる継承を分け、
  未実施の人による本編全時間の連続視聴/試聴を実施扱いにしない。
  採用先の変更は新しい制作記録・最終QA・参照画像・素材管理の全体検査をそろえて行う。
  この手順の実行だけで共通カタログの採用先を自動変更しない。
