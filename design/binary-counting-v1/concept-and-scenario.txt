二進数カウント第1話：企画・シナリオ
版：binary-counting-v1 / 2026-11-10 JST
段階：制作前の設計資料。新規音声の採用、二進数動画の実装・書き出しは未実施。

1. この版の設計基準

赤いベレー帽のクマと、穏やかな薄青紫の夕暮れのlantern-gardenを使う。生成済み背景を全編の基準とし、昼から夜へ変わる時間経過表現は採用しない。具体的な背景画像参照・hashはepisode-plan.jsonを正本とする。背景、既存の正本クマ、数字表示は別レイヤーで組む。

仮の範囲は、十進数の値0から127までの128状態。二進数表示は0から1111111まで。各桁を英語で左から順にzero / oneと読む。範囲と尺は実音声・可読性の確認後に確定する。前作の8分以上9分未満という尺方針を今回も引き継ぐ前提の企画見積もりであり、新たな依頼条件として断定しない。

全128行の数列、display_binary、spoken_tokens、spoken_textはcount-lines.json / count-lines.tsvを参照し、この文書には重複列挙しない。episode-plan.jsonが構成、estimated-timeline.jsonが仮タイミング、script-and-sound-cues.txtが英語台詞と音を管理する。

2. 視聴者に伝えること

- 二進数はzeroとoneの2種類の数字を使う。
- 数字列は左から右へ1桁ずつ読む。10は、この動画ではone zeroと読む。
- 10の値は十進数の2。大きい二進数表示と、小さいEveryday numberの補助表示を区別する。
- 明るいセルは1、消灯色のセルは0。値は点灯セルの個数ではない。
- 使用していない先頭の場所は空欄で、0と区別する。空欄は読まない。
- 桁上がりを考える向きは右から左だが、声に出して読む向きは左から右。

3. 画面の情報階層

主表示は、横一列に固定した7個の桁位置。右詰めで必要な桁だけ数字を入れる。0も右端の1セルを使用する。上位の未使用セルは空欄のままとし、数の長さに応じて右端位置を動かさない。

0はoff lavender、1はwarm gold。両方に大きい0 / 1の字形と明瞭なセル境界を付け、色だけに意味を依存させない。未使用の先頭位置は空欄と控えめな枠で示し、0の字形や消灯ランプを置かない。背景内の装飾ランタンは桁の表示と結び付けない。

桁の重み64 / 32 / 16 / 8 / 4 / 2 / 1は別の補助行に小さく配置する。Everyday number: nは独立した補助captionとし、重みの行と混ぜない。重みもcaptionも通常カウント中には読まない。大きい二進数の視認性を優先する。

発話位置はセル下のunderlineだけで示す。数字の位置・大きさ・内容は1つの数を読み終わるまで固定する。現在の桁の声に同期してunderlineを左から右へ移す。クマの指差し、口パク、視線追跡、eye rigは未実装で、この企画の実現済み機能として扱わない。

4. 導入と本カウントの分離

冒頭0.00-0.80秒は無音。導入は合計32秒の仮枠で、英語8本・57語。独立したHOW TO READ画面で0と1、読み方向、例の10とEveryday number: 2を示す。例の10は本カウントの先行表示ではなく、練習例である。

HOW TO READ画面では説明対象の小さい2だけを強調し、重みの行は出さない。最後の台詞の後に練習例を片付け、32.00秒から本カウントを0で開始する。練習例と本カウントを同じ進捗ストリームとして扱わない。

5. カウントと桁上がりの見せ方

各状態の基本構造は、prehold 0.12秒 → 実音声に従う桁読み → posthold 0.18秒。桁間の仮の無音は0.055秒。これらは制作時の再計算対象で、単語の尺を揃えるタイムストレッチは行わない。oneとzeroは別の自然な長さでよい。

2 / 4 / 8 / 16 / 32 / 64の前だけ、短いSE_PLACEをprehold内で鳴らす。主カウンタは直前値から次の正しい値へ一括更新し、桁上がり途中の000や誤った中間値を主表示の数として見せない。説明が必要な7→8と63→64では、独立した比較カードの111→1000、111111→1000000を使う案とする。比較カードの右から左へのcarryと、本カウンタの左から右へのunderlineを区別する。

0：右端に0、消灯色セル。未使用の空欄との差を示す。
1：同じ右端セルが1になる。
2（10）：新しい左の1と右の0。commit後にone zero。
3（11）：点灯セルは2個でもEveryday numberは3。点灯数を値として説明しない。
4（100）：左に新しい1、右に0が2桁。誤った中間値を主表示に出さない。
7→8：3秒の独立した説明枠。次に1000を読む。
15→16：通常進行のまま短い視覚cueとSE_PLACE。説明台詞は追加しない。
31→32：31を保持して8秒のstretch。終了後に100000を読む。
63→64：3秒の独立した説明枠。次に1000000を読む。
127（1111111）：7桁すべて1を保持し、15秒のfinaleへ。128へ進まない。

6. 8状態ごとの演出

decimal_valueが7 / 15 / 23 / 31 / 39 / 47 / 55 / 63 / 71 / 79 / 87 / 95 / 103 / 111 / 119 / 127で、合計16回のcheckpointを設ける。0開始なので8状態ごとの位置は(n+1) mod 8 = 0。

7は3秒のplace説明、31は8秒のstretch、63は3秒のplace説明、127は15秒のfinaleに統合する。他の12回は背景の穏やかな光・小さな装飾反応のみ。最後の桁を読み終わったところから0.8-1.2秒継続しても、次のカウントは止めない。追加台詞・SE・全画面切替は付けない。数字・underline・captionを隠さない。

checkpointと次の新しい桁のcueが近接する場合も、背景cueを弱く保ち、SE_PLACEは次の数のpreholdだけに置く。可読性、発話同期、安定したカウンタを優先し、背景色や空の時刻を変えない。

7. クマの扱い

通常カウントは既存canonical bodyを基準にする。登録済みthink / wave / stretchを、説明・挨拶・休憩で使う提案とする。支持点、自然高、登録translationを尊重し、ポーズごとに可視bboxへ合わせて拡大しない。無条件反転や別キャラクター化は行わない。

導入の挨拶：登録waveの候補。
HOW TO READと7 / 63のpause：登録thinkの候補。
31のstretch：登録stretchの候補。
finaleのBye for now!：登録waveの候補。
通常の数字読み：canonical bodyを保持。

これは新テーマへの配置・実装提案。登録済みポーズが新しい動画の動作を保証するものではない。指差し・口パク・eye rigの追加を前提にしない。

8. 音と仮の尺

BGMなし。風、砂の擦れ、static、環境ノイズのSEなし。発話間やpauseの余白はdigital silence。数字の声に説明台詞やSEを重ねない。

SEは2種類・合計7回。未生成のSE_PLACEを6回、既存SE_FINISHをfinale冒頭に1回。通常checkpointには音を足さない。SE_FINISHはfadeとtail込み1秒の既存仕様を使い、台詞の前に終了させる。

仮の本カウントは、oneが448語、zeroが322語、合計770語。内部の桁間は642箇所。既存oneの実測尺0.47583333333333333秒を基準に、zeroのみ未実測0.52秒を仮置きする。

448×0.47583333333333333 + 322×0.52 + 642×0.055 + 128×0.30
= 454.3233333333333秒（本カウント）
32秒intro + 3秒after7 + 8秒after31 + 3秒after63 + 15秒finale = 61秒
合計515.3233333333333秒 = 約8分35.32秒。

SE_PLACEとSE_FINISHは既存の無音窓に置くので、この計算に追加の時間を足さない。finaleの最後の13-15秒はcream fade。声はfade開始前に終える。

zeroが仮値より0.04秒長いだけで全体は12.88秒伸びる。実音声の確認後に状態ごとのholdを0.12-0.35秒の範囲で調整する案とし、初期の短い数を長めに保持する場合も全体を再計算する。127までの範囲や9分未満を先に確約しない。

9. 実制作へ進む前の実装課題

既存TTS・検査・rendererは十進数の1開始を前提としており、二進数の0開始・空欄セル・spoken_tokens照合は未実装。計画データがあるだけでproduction-readyとは扱わない。

- zero、新しい導入、place説明、Seven places, all ones!の候補は別版へ生成し、現行v002の採用資産を上書きしない。
- 既存oneと台詞はmeasurements・本文・profile・SHA256を照合して再利用する。
- zeroは単独で認識・音素・音響・聴取を確認し、文脈ASRだけで警告を解除しない。
- 二進数音声はzero / oneの列そのものを照合し、zeroを捨てる整数化や十進数読み検査へ流用しない。
- 全128状態の順序、表示、発話token、underline順、blank、captionの値、carryの一括commitを検証する。
- 新背景上でポーズの支持点・自然高・表示領域・数字の遮蔽を確認する。
- 実音声でtimelineを再計算し、範囲と尺を確定する。

本資料の対象は新企画の制作設計まで。既存第1動画、既存音声、active catalog、episode登録を変更しない。
