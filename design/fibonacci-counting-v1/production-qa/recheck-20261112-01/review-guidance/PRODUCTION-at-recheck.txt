# 既存作品の再出力と新作の制作

別PCのセットアップが済んだら、まず採用済みの原画・音声・実測タイムラインで再出力します。モデルから音声を再生成することは、既存完成品の再現とは別の工程です。

## 既存作品を再出力する

```powershell
python tools/portable_production.py list
python tools/update_production_archive.py --check
python tools/portable_production.py doctor
```

`--production` には `decimal`、`binary`、`octal`、`hexadecimal`、`four-base`、`even`、`odd`、`prime`、`fibonacci`、またはカタログの現行制作セットIDを指定します。

```powershell
$workRoot = if (Test-Path 'D:\') { 'D:\temp\num-num-numbers' } else { Join-Path ([IO.Path]::GetTempPath()) 'num-num-numbers' }
python tools/portable_production.py preview --production four-base --out-dir output/four-base-preview-new --work-dir $workRoot
python tools/portable_production.py render --production four-base --out-dir output/four-base-render-new --work-dir $workRoot
python tools/portable_production.py verify --production four-base --video output/four-base-render-new/paspla-studio-four-ways-to-count-0-to-200-1080p.mp4 --out-dir output/four-base-render-new/qa --work-dir $workRoot
```

出力先の動画、字幕、チャプター、タイトル・概要を確認します。既存完成品を上書きせず、完成MP4を対象とする検査を終えてから採用先を切り替えます。

`preview` / `render` の出力先は未存在のフォルダを指定します。`verify` には確認する `--video` と未使用のQA出力先を渡します。元のレンダーフォルダをQA出力先に使いません。`--timeline`、`--audio`、小鳥用の `--motion-manifest` を省略すると採用原本を使います。別の設計入力を用意した場合は、それぞれを明示して描画・検査できます。

移植用 `verify` は全9作品で完成MP4を全編デコードし、形式・フレーム数・音量に加え、最終AACを採用音源と照合して予定外の音や無音区間を確認します。作品ごとの追加範囲は次のとおりです。

| 対象 | 追加する検査 |
|---|---|
| 十進数 | 全345音声イベント（312発話・33効果音）と346無音区間の照合、原寸代表7要素の配置 |
| 二進数 | 全770桁の発話波形と実映像、642か所の桁間0.9秒、127数境界（通常124か所は2秒）、字幕、十進数看板と中央揃え |
| 八進数・十六進数・4基数 | 全数値の表示サンプル、発話前後の同期、採用音源・無音区間の照合と各作品の配置 |
| 偶数 | 全101値の表示・発話境界606場面、代表35場面、積み木の個数・組、一の位の見本、115発話の左右音声と字幕 |
| 奇数 | 全150値にわたる全フレームの主数値・英語読み・7整数欄の独立した字形照合、原寸19場面の切符の個数・組、99→101、図のフェードと完了印、163発話の左右音声と字幕 |
| 素数 | 全168値・全カウントフレームの主数値・英語読み・約数2欄、原寸229場面、陶片の個数とフェード、188発話の左右音声と字幕。v003の演技・進捗は独立検査も実施 |
| フィボナッチ | 全41項・39式の入力と結果、項の添字、受渡し、3例の繰り上がり、全項一覧、104発話の左右音声・無音と字幕 |

新しいASR・CTCの推論と人による全編試聴は別工程です。過去の認識・採用記録を検証した結果と、新しく再認識した結果を分けて記録します。

奇数作品では最終AACの全163発話を新規ASR・CTCで再認識する制作QAも設け、`odd` の移植用 `verify` と区別して根拠を保存します。移植用検査だけを再認識の実施記録として扱いません。

小鳥の現行レシピを新しい場所へ組み直す場合は、次で0〜200の実測計画と音声マスターを作れます。

```powershell
python tools/portable_production.py build-four-base --out-dir output/new-four-base-inputs --design-dir design/new-four-base-inputs --work-dir $workRoot
```

数の範囲、基数、台詞や画面構成を変える新作では、新しい版の設計・準備・描画・字幕・検査ツールを揃えます。既存レシピの数の範囲とscene構成は各制作記録の仕様に対応しています。

同じ原本でもFFmpeg、フォント描画、エンコーダーの版等によってMP4のbytesやSHA-256は変わることがあります。新しい出力のSHAだけを旧完成品と比較して合否にせず、表示、時刻、フレーム数、音量、音声内容も検査します。

## 作品ごとの重要な条件

| 十進数 | 1〜300の自然な英語読み。青空の庭、既存のくま、BGMなし。効果音は採用脚本どおり |
| 二進数 | 全128値・770桁。桁間0.9秒。通常の数の読み終わりから次の数まで2秒。十進数の看板、文字の中央揃え |
| 八進数 | 全128値・312桁。桁間0.9秒。通常2秒。読み上げ文字の共通ベースラインと等間隔。ピンクのウサギ |
| 十六進数 | 0〜7F、全240桁。桁間0.9秒。通常2秒。単独Aは明瞭な採用版を使用 |
| 4基数同時 | 十進0〜200、201値・804表記。音声は十進数の自然読み。通常197境界2秒、説明3境界5秒。200で終了 |
| 偶数 | 十進0〜200を2ずつ、101値。通常98境界2秒、20と100の説明2境界10秒。0も偶数として扱い、200で終了 |
| 奇数v002 | 十進1〜299を2ずつ、150値。通常147境界2秒、9と101の説明2境界10秒。表示先行0.12秒、299の読み終わり後0.28秒保持。完成映像8分55.80秒・16074フレーム |
| 素数v003 | 1000未満の素数2〜997、168値。通常164境界2秒、2・7・97の後の説明3境界18秒。表示先行0.12秒、997の後0.28秒保持。完成映像11分26.33秒・20590フレーム。案内・拍手・休憩と発話完了後の進捗モザイクを追加 |
| フィボナッチv001 | F₀=0〜F₄₀=102,334,155、41項・39加算。二つの1を保持。通常34境界は前の値の読み終わり→次の式または数の読み始め2秒、説明6境界。結果は読みの0.12秒前に確定。8分56.47秒・16094フレーム |

台本で説明・休憩のために延長した境界は、通常2秒より長く設定されることがあります。キャラクターだけの静かな姿勢変化を理由に、音声の境界を自動的に延長しません。具体的な間隔は各 `timeline.json` と制作記録に記載されています。数の最後の発話が終わってから次の数の最初の発話が始まるまでを測り、表示開始時刻との差と混同しません。

小鳥の4基数同時動画は、短い挨拶の羽ばたき、48の後のついばみ、96の後の12pxのホップを一度ずつ使います。通常姿280px、足元 `(1675, 950)`、共通の登録基準を維持し、しゃがむ姿や広げた翼を枠に合わせて拡大しません。

偶数動画は木のおもちゃ工房で同じ通常姿を使い、積み木の二個一組、20個の十組、100の一の位の確認を示します。小鳥の過去の演技は追加していません。`even` の再出力は採用済みマスターを使い、新規TTSやモデルの準備は不要です。

奇数動画は山のケーブルカー駅でレッサーパンダの通常姿を420px高、足元 `(1615, 950)` に固定します。切符の二個一組と一つの余り、99から101への加算を示し、主数値・見出しを固定したまま説明図を空欄へフェードします。BGMと効果音はありません。`odd` も採用済みマスターから再出力できます。

素数v003は `prime` でプレビュー・再出力・完成品検査に対応します。描画は `tools/render_prime_video_v003.py` と `tools/kangaroo_animation_v003.py`、動作時刻は `output/prime-counting-001-v003/kangaroo-motion.json`、採用素材と支点は `assets/library/characters/kangaroo/animations/prime-v002/registration.json` を使います。新規12原画と既存15原画の計27原画・29状態を登録し、`aha` は `present_point`、`settle` は `wave_raise` を明示的に再利用します。470px高・足支点 `(1625, 1014)` の通常姿を土台に腕と上胸だけを合成し、手振り時の頭・胴体の跳ねを抑えます。教材を示す3姿、同じ顔を保つ拍手3姿、約12秒の座る・伸びる・休む・立つ流れを追加しました。シートごとの共通物理縮尺と足支点で描画し、しゃがみ・座位を個別に拡大しません。通常カウントの進捗モザイクは、表示開始で先取りせず、各数の音声が終わった後に1枚ずつ増えます。

v003の再出力はv002の最終AAC（v001と同一）をコピーし、出力後もビット列の一致を確認します。元タイムライン・PCMマスター・発話時刻が変わった場合は、同じAACを流用できると判断せず停止します。採用済みマスターは音量調整を含み、追加ゲインは加えません。v001・v002のMP4・採用音源・タイムラインはv003の再現依存先でもあるため残します。原音からマスターを組み直す場合は、新しい出力先と `python tools/build_prime_episode.py --out-dir output/new-prime-inputs --balance-rms-dbfs -19` を使い、新しい音声として検査します。

素数の原音と最終AACの新規ASR・CTCは、v001の制作QAとして保存しています。v003には、v002を経由したAAC全パケットの内容・時刻の完全一致を根拠に、その発音確認を継承しています。新たに再認識した場合は、対象版と実行結果を別記録に残します。数値・音声・字幕検査と、演技・進捗の独立検査の範囲は [制作レビュー](../design/prime-counting-v1/production-review-v003.txt) と [制作記録](../design/prime-counting-v1/production-run-v003.json) に保存しています。完成品検査は `output/prime-counting-001-v003/qa/v001/verification.json`、演技・教材・進捗の独立検査は `design/prime-counting-v1/production-qa/v003-comparison/final-003/verification.json` です。全20,590フレームの教材・演技、32状態の静止画への置換を検出する対照、AAC全32,173パケットの内容・時刻の一致を確認しました。進捗は全169状態と可視20,579フレームを照合し、白に近いフェード11フレームは視認上の測定対象外としています。無フェード20,506フレームの進捗グループは水平差0px・垂直差最大0.5pxで、両軸とも完成映像の1px許容差内です。v001・v002の記録を新版の検査結果として書き換えません。

フィボナッチは `fibonacci` で採用マスターと固定したキャラクター参照から再出力できます。マスターの音量調整を二重に加えません。原音から組み直すときは `tools/build_fibonacci_episode.py` を使い、音声採用ゲートと `speech/aac-scalar-corrections.json` の源SHAを確認します。AACの実測で見つけたT013bのピーク超過は、その発話全体への一定-2.5dBで校正しました。最終マスターを使う再出力へ、この補正をさらに適用しません。新しく符号化した完成AACの音量・ピークは再検査します。詳細は[制作レビュー](../design/fibonacci-counting-v1/production-review-v001.txt)に保存しています。

## 新作の設計

企画の初めに選定したキャラクターを伝え、脚本・台本、背景コンセプト、画像モックアップを用意します。ユーザーの指定がなければ、キャラクターは登録済み素材からランダムに選定して構いません。

ショート動画以外は原則1本8分以上とします。尺を満たすために数の間隔や読み速度などの視聴感を変えず、既存の通常2秒の間隔を保ち、範囲を区切りのよい終点まで広げます。Shortsまたはユーザーが明示した例外だけを別扱いにします。偶数の6分版など過去の完成品は当時の仕様・尺の履歴として保持します。

企画時に採用音声の実測長と待機時間から完成尺を確認します。奇数v002は範囲を1〜299へ広げ、確認のある2境界へ各8秒を加えます。数詞150発話の合計をS秒とすると全尺はS+364.40秒です。PCM実測合計171.380916666667秒、音声尺535.780916666667秒に対し、完成MP4の映像尺は535.80秒（16074フレーム・30fps）です。

1. `design/<新しい企画>/` に、対象年齢、数の範囲、表示する基数、ナレーションの読み方、目標尺を明記する。
2. 脚本と英語台本を作り、導入、通常カウント、お題に必要な説明・節目、終幕を分ける。各台詞にIDと編集枠を付ける。
3. 一つの十進値を真値として、全ての表記・音声・字幕を同じ状態に結び付ける。全値の対応表を作る。
4. 背景は数字やキャラクターを焼き込まない原画として保存し、植生、地域、季節、色をテーマに合わせる。
5. 先に選定・通知したキャラクターの通常姿、足元支点、自然高、動作の最大幅を調べる。線幅、顔、体格、縮小品質を原寸で比較する。
6. 導入、通常画面、お題に必要な説明・節目、最大桁数、終幕のモックアップを作る。最も長い数値や文字列も同じ文字サイズで収まるか確認する。
7. 音声の実測長から尺を確定し、編集枠と動作を調整してから本番を描画する。

### お題に合わせた構図と背景

新作ごとに、数の性質・説明の順序・キャラクターの役割から画面構成を設計します。前作の「キャラクターを右または左に固定し、反対側に大きな数値カードを置く」配置を既定のテンプレートとして流用しません。左右の交代や反転だけで構図の変化とせず、お題に合う見せ方を毎回考えます。

- 台帳が指定する過去作品の実画面と比較し、新作の背景コンセプトは過去作品と重複させない。同一舞台の再利用をユーザーが指定した場合は、その指定と意図を仕様に記録する。教材の置き方、キャラクターの位置・大きさ、視点、画面の主役も検討し、背景の色やキャラクターを替えただけで比較を済ませない。
- 中央で教材を扱う、下部から案内する、教材を囲む、全景と寄りを使い分けるなど、学習内容に役立つ構図を選ぶ。これらは候補であり、順番に使い回す固定パターンにはしない。
- 導入・説明・通常カウント・節目・終幕の役割に合わせて画面を構成する。組分け、受渡し、増え方、完成までの進捗など、お題そのものから視覚的な変化を作る。同じ配置を長く使う場面も、意味に沿った変化や案内を検討する。
- 数字・読み・図の見やすさと視線の流れを優先し、構図の切替や移動は学習の流れに合わせる。長い数値、最大桁数、指さし、伸び、跳躍、遷移途中でも、意図しない教材の遮蔽・文字切れ・図形との衝突がないか確認する。教材を持つ・触れるなど意図した接触は、意味と読みやすさを保つ形で設計する。
- 絵コンテと制作仕様に、採用した構図の理由、キャラクターと教材の関係、過去作との差、場面ごとの変化を記録し、全画面のモックアップで確認する。

### キャラクター演技と不足素材

通常姿が表示されることや、まばたきがあることだけで演技が十分と判断しません。クマを含む過去作品の完成MP4と、原寸・全画面・連続した動作プレビューで比較し、そのキャラクターとお題に必要な表情・仕草・姿勢変化が揃っているか確認します。素材枚数、動作率、表示サイズ、静止の秒数を全作品共通の固定目標にはせず、今回の素数動画の数値も一律には適用しません。

- 挨拶、教材を示す動作、考える・気づく反応、節目の喜び、静かな待機・着座・伸び、終わりの挨拶などから、脚本に合う演技を選ぶ。長いカウントは短い抜粋だけで判断せず、変化の乏しい区間と演技の繰り返し方も確認する。
- 不足する表情、手の開閉、動作の途中、屈伸・踏み切り・着地などは新規生成する。既存素材を無理につないで不足を残さず、良好な素材は再利用する。素材を増やしただけで完了にせず、動画へ組み込み、必要な動きとして読めるか確認する。
- 採用通常姿の顔・体格・色・質感を保ち、シートごとの校正済み共通縮尺と足元支点を使う。屈伸や座位を個別の外接矩形で拡大しない。手だけを動かす場面で頭・胴体まで意図せず跳ぶ切替、二重の顔・手、残像、輪郭の欠け、表情のちらつきを不合格とする。意図した頷き・屈伸・移動などは、動作と支点の関係を別途確認する。
- 複数の中間姿勢は、接近と戻りの両方向を確認する。拍手中に顔が高速で開眼・閉眼を繰り返すなど、仕草と関係のない部位の変化を避ける。指さし・視線は実際の教材の方向と対応させる。
- 新規原画、派生セル、再利用、別名による状態を区別して記録する。登録状態数や別名を、新規生成した独立原画の枚数として数えない。生成条件と原画の保存は [画像管理仕様](IMAGE-ASSET-MANAGEMENT.md) に従う。

原画の身体基準・足元支点と、画面上の配置を区別します。共通縮尺は、同じ場面・表示尺度で使う動作群に適用します。お題や構図に合わせて場面ごとの表示サイズ・位置を変える場合は、その場面の身体基準高、画面上の支点、意図した移動の軌跡を定義し、同じ換算を全動作へ適用して遷移を確認します。配置を合わせるために原画の登録基準を書き換えません。

新作の輪郭は各キャラクターの採用通常姿を基準に、実際の表示サイズで比較します。小鳥の現行構図での局所約7pxはその作品の参考値であり、全キャラクター共通の線幅目標ではありません。体格・帽子・元画像の解像度を理由に画質の不足を見逃さず、線幅・濃淡・質感と、動作への切り替え時の線や体格を確認します。

目立つ演技は、数値の読みや切替を妨げない間へ置きます。静かな着座や姿勢保持は発話中にまたがって構いませんが、読みのテンポと教材への注意を保ちます。同じ動作の常時ループや毎作同じ演出の追加を避け、学習内容や場面に合うものを選びます。

枠内で上下左右中央揃えを意図した全コンポーネントは、実描画の可視範囲で水平・垂直の中心をそれぞれ検査します。片軸だけの一致、はみ出し、文字切れ、未検出を合格にしません。[中央揃えの受入仕様](LAYOUT-ALIGNMENT.md) に従い、モックアップと完成映像で両軸の差・許容差・合否を記録します。

## 画像素材の並行生成・管理

複数のAIが画像を生成するときは、[画像管理仕様](IMAGE-ASSET-MANAGEMENT.md) に従って担当と専用バッチを予約します。生成中の原画・候補を別担当が動かさず、共通台帳の更新は管理担当が直列に行います。用途・担当・確定在庫は [管理一覧](../assets/library/character-assets.html) から確認できます。

共有ストック、作品専用素材、制作準備用、未採用候補を区別します。画像が保管・在庫登録されただけでは新規採用にせず、従来作品の選択や表示を変更しません。透過・ハッシュ・画素由来の合格と、輪郭・色味・顔・紙目・動作の合格も別々に記録します。[詳細な画風監査](../assets/library/collections/character-style-audit/v001/index.html) の要修正指摘は、元の採用履歴を保ったまま品質情報として追跡します。

## 音声を再利用・新規採用する

採用済みの `measurements.json` と `speech-acceptance.json` を優先します。本文、voice、model、速度、dtypeが異なる音声を既存採用版として扱いません。

別PCで既存ライブラリを新作へ再利用する場合は、元のゲートを変更せず、現在のcloneに対応する派生ゲートを作ります。

```powershell
python tools/portable_speech_library.py --library assets/library/audio/speech/kokoro-af-heart/v002 --out-dir output/new-local-speech-gate
```

この処理は採用WAVと検査根拠のSHA-256を検証します。履歴に残る元PCの絶対パスは派生記録で解決し、元の採用記録・原音・根拠を上書きしません。

新しい音声を作る場合の流れは次のとおりです。

1. 未使用の候補フォルダへ生成し、生成文、声、モデル、速度、切り出し・fade・padとSHA-256を保存する。
2. 正解文や隣の数字を入力しない単独ASRで確認する。
3. 独立CTC音素、語末、波形、必要な試聴で余分な母音、子音欠落、反復、途中切断を確認する。
4. 警告ごとの判断と根拠を残し、未解決のまま採用しない。
5. 採用ゲートと実測マニフェストを作成してからミックスする。

ASRの数値一致や原音との波形一致だけでは、原音に含まれる発音上の不備を検出できません。偶数v002では、無声の摩擦音で始まる数詞の先行有声音も調べ、問題のあった6語を別テイクへ置き換えました。完成AACでも語頭・語尾と認識器の差分を確認します。図のフェードは、静止した代表画像だけでなく途中フレームで文字が重ならないことも確認してください。

関連ツールは `generate_speech.mjs`、`generate_speech_candidates.mjs`、`verify_speech.mjs`、`verify_phonemes.mjs`、`verify_terminal_tails.py`、`review_speech_acceptance.mjs` です。個別CLIの元PC固定パスには注意し、[セットアップ](SETUP.md) と各ツールの引数を確認します。

別PCで新規候補を作る場合は、移植用の候補生成・音素検査を使います。`jobs.json` は `id` と `text` を持つ配列で用意します。出力先は未使用の候補フォルダにします。

```json
[
  {"id": "intro-new", "text": "Let's count together."}
]
```

```powershell
node tools/portable_speech_candidates.mjs --jobs jobs.json --out output/new-speech-candidates --cache $modelCache
node tools/verify_speech.mjs --manifest output/new-speech-candidates/manifest.json --cache $modelCache --ffmpeg ffmpeg --out output/new-speech-asr.json
node tools/portable_verify_phonemes.mjs --takes output/new-speech-candidates/takes.json --cache $modelCache --ffmpeg ffmpeg --out output/new-speech-phonemes.json
```

英語本文 `text` を指定した候補からは、生成ツールがASR用 `manifest.json` を同時出力します。生成来歴を含む `takes.json` と測定マニフェストは形式が異なるため、入力を取り違えないようにします。候補生成だけでは採用になりません。

数値の意味が文脈の中で認識できても、単独音声の発音警告を消す理由にはしません。自動認識の一致を、人による全件試聴や発音の完全な保証として記録しません。

## 完成MP4の検査と登録

- 技術検査と、演出・素材・構図の品質判断を分ける。予定した画像との一致、正常なデコード、ハッシュ一致だけで「過去作と同程度に十分」と判定しない。完成MP4を実際にデコードし、過去作との比較、原寸の動作のつながり、全画面での読みやすさ、長い区間の変化を確認する。
- 選んだ表情・中間姿勢・仕草が完成MP4に反映され、頭・身体の意図しない跳ね、二重像、ちらつき、切れがないことを確認する。必要に応じて静止画への置換などの負の対照を使い、検査が見つけるべき不備を実際に検出できることも確認する。不足があれば素材生成・組込みへ戻る。
- 数の範囲・個数・順序・例外・説明式を独立に確認し、表示・図・台本・字幕・音声の対応を照合する。テーマ固有の進捗や個数の演出も実映像から検査し、読み終わりなどの更新基準を明記する。
- 中央揃えを意図した枠内要素は、最終デコード画像でも上下・左右の中心を独立に照合し、原寸の余白とはみ出しを確認する。基準は [中央揃えの受入仕様](LAYOUT-ALIGNMENT.md) を使う。
- 全編デコード、1080p30fps、映像・音声の終端、色タグ、フレーム数、AAC、音量とtrue peakを確認する。
- 全数値の前後、発話直前・開始・終了・直後、お題に必要な境界・説明（桁上がりなど）、最後の値、フェードを確認する。
- 長い数値は行全体だけでなく各桁も照合し、更新途中の異なる値の混在、空白、文字切れを探す。
- 最終AACを採用WAVと照合し、読み間違い、音切れ、予定外の音、クリップ、同期を確認する。
- 左右音声の差は、ソース、エンコード、時間・音量を調べて判断する。AACへ符号化した後の左右の波形が完全一致するという前提は置かない。
- 字幕、チャプター、タイトル・概要が実測タイムラインと完成範囲に合うことを確認する。
- 完成品と依存ファイルをSHA-256で束ねた制作記録を保存し、検査後にカタログの採用先を切り替える。

既存の制作記録・検査記録はその時点の証拠です。新しい検査を追記する場合は別フォルダへ保存し、前回の結果を書き換えて合格にしません。

比較に使った作品、構図・演技の判断、不足素材と対処、検査方法・範囲・対象外を記録します。自動解析、抽出画像・動作抜粋の確認、人による全編連続視聴・試聴を区別し、実施した範囲に即して結果を伝えます。映像だけを改訂して音声を継承する場合も、最終音声のデータと時刻を照合し、新しく発音を再認識した検査とは区別します。

今回の注意点の根拠は [素数v003の比較・制作レビュー](../design/prime-counting-v1/production-review-v003.txt) に保存しています。今後の新作には上の共通仕様を適用し、過去作品の採用構図・媒体・当時の検査記録は、この仕様追記だけでは変更しません。

## 再現用入力をGitへ追加・更新する

新作・新版の検査と制作記録を確定し、カタログの採用先を更新してから実行します。

```powershell
python tools/update_production_archive.py --write
python tools/update_production_archive.py --check
git lfs status
git status --short
```

`--write` はカタログから必要な入力を再計算し、`reproducibility/production-inputs.json` と `.gitignore` の管理マーカー内の許可リストを更新します。`--check` はこれらの一致とファイルのSHA-256を確認し、ファイルを変更しません。収納方針は `reproducibility/archive-policy.json` にあります。

差分で採用原本、作品固有の台詞、実測timeline、master、動作情報、必要な根拠が揃っていることを確認してコミットします。全 `output/` を強制追加してキャッシュや未採用候補を混ぜないでください。Gitの行末正規化で原本のSHA-256が変わらないよう、`.gitattributes` の設定も維持します。
