# 画像素材の管理・並行生成仕様

この仕様は、動物・植物・乗り物・昆虫・虹などの画像素材を、原画・候補・採用版・作品別素材として管理する規約です。担当予約から生成、比較、品質確認、採用、引き継ぎまでを扱います。管理在庫への収録と、実際の採用は別の操作です。

画像を使うだけの場合は [素材利用ガイド](../assets/library/README.md) を入口にします。出力標準と作品全体の検査は [制作仕様](PRODUCTION.md)、実描画の配置は [配置受入仕様](LAYOUT-ALIGNMENT.md)、配布範囲とGitHubへの同期は [GitHub公開仕様](https://github.com/anoneunknowns/youtube/blob/main/docs/GITHUB-PUBLICATION.md) が正本です。制作原本の事例資料は、素材ZIPや公開版への同梱を保証しません。

## 作業の進め方

| 工程 | 完了を判断する根拠 |
|---|---|
| 対象を決める | 現行の採用先、具体的な不足、改善条件、変更しない画像と登録 |
| 担当を確保する | 衝突しない保存先と所有者の予約 |
| 候補を作る | 無改変の原画、正確なプロンプト、入力の役割とSHA-256 |
| 比較・検査する | 同一尺度の原寸・明暗・最大表示・前後姿勢、必要な圧縮確認 |
| 採用する | 明確な改善と退行の有無、ユーザーの選択または委任、採用根拠の記録 |
| 共通ビューを更新する | 直前の `current/` の保全、登録・台帳・派生PNGの整合、変更対象外の照合 |
| 引き継ぐ・公開する | 担当完了、在庫と全体検査、用途に応じた公開範囲と取得実体の検証 |

同程度・判断不明・悪化なら既存を維持します。生成枚数や版番号を増やすことを目的にせず、良好な素材を残します。詳しい採否は [選択から採用への反映](#選択から採用への反映) に従います。

## 正本と管理する情報

### 台帳の役割

| 正本・入口 | 用途 |
|---|---|
| [`catalogs/asset-library-current-v1.json`](../catalogs/asset-library-current-v1.json) と各 `current/asset.json`・`clips.json` | 全素材の共通入口、利用PNG・ポーズ・動作・登録座標 |
| [`catalogs/character-library-v1.json`](../catalogs/character-library-v1.json) | 採用元をまとめたINDEXと互換ローダーの入力 |
| [`catalogs/character-adoptions-v1.json`](../catalogs/character-adoptions-v1.json) | 通常姿・短い演出の明示採用と選択・品質の根拠。過去QAを改変せず採用先を切り替える |
| [`catalogs/library-v1.json`](../catalogs/library-v1.json) と作品の制作記録 | 作品固有の採用先 |
| [`catalogs/character-asset-management-v1.json`](../catalogs/character-asset-management-v1.json) | 管理設定、担当予約、分類、選択・品質の根拠 |
| [`catalogs/character-asset-registry-v1.json`](../catalogs/character-asset-registry-v1.json) | 管理設定から作る在庫 |

管理用の在庫・一覧は、未分類・未採用を含む生成バッチ全体を把握するために使います。収録、ハッシュの一致、`v003` 等の版番号は、採用や画風合格を意味しません。更新・検査には [`tools/manage_character_assets.py`](../tools/manage_character_assets.py) を使います。

設定の各 `batches` に `root`、担当 `owner`、用途 `scope`、分類 `state`、`registration_paths`、`selection_evidence`、`quality_reviews` を明示します。用途が不明な新規バッチは `unclassified` のまま追跡します。

### 来歴・進行・品質・採用範囲

| 情報 | 記録する内容 |
|---|---|
| 来歴 | 作業ID・所有者、生成／編集日時、正確な指示文、入力と出力、SHA-256 |
| 作業の進行 | 生成中、受領済み、候補、引き渡し、保管などの状態と根拠 |
| 品質・検査 | ファイル整合、画素由来、静止画、画風、動作、完成作品ごとの検査範囲・合否・要修正箇所 |
| 採用範囲 | 通常姿、共有ストック、特定作品用、制作準備用、未採用と、選択の根拠 |

設定の `state` は `canonical`、`shared_stock`、`episode_selected`、`preproduction`、`candidate`、`archive`、`unclassified` の用途分類です。生成中かどうかは `reservations` の所有者と `active`／`released`、品質は `quality_reviews` で管理します。

現在の `needs_revision` と、過去の作品で選択された事実は共存できます。過去の採用履歴と当時の検査記録を残し、新しい指摘と判断を対象・範囲付きで追記します。現在の判定へ書き換えて過去の事実を消しません。不要な旧媒体は [削除手順](#不要旧版を削除する場合) の優先度に従って整理し、必要な原画・現在のQA根拠と当時のパス・SHA・採用・検査記録を保護します。

## 並行作業の担当と保存先

1. 生成開始前に管理設定の予約を確認し、キャラクター・用途・作業ID・担当AI／作業者・保存先を予約します。作業IDには日時に加えて、タスク識別子と衝突しない固有識別子を含めます。別のAIが同じ `motions/v002` 等を独立に確保してはいけません。
2. 生成担当は自分のバッチ内だけへ書き込みます。共通台帳・採用先・ファイル一覧の更新は管理担当一人へ集約し、同じAIが複数役割を担う場合も書き込みを直列にします。
3. 生成中の予約があるバッチを、他担当が移動・削除・改名・上書きしません。管理側は生成中として追跡し、未完了のファイル集合を確定在庫として扱いません。
4. 所有者が完了を宣言し、画像と来歴の保存・検査を終えてから管理へ引き渡します。引き渡し後の追記も担当と内容を記録し、登録中に無断で支点や画像を更新しません。

新規作業は、例えば次のように衝突しないバッチへまとめます。

```text
assets/library/characters/<character-id>/generation-batches/<unique-batch-id>/
  source/          元生成画像・元編集画像の無改変コピー
  candidates/      不採用案・再生成前の案・却下理由
  frames/          採用候補の無損失セル抽出等
  previews/        明暗比較・拡大図・動作確認用の動画やGIF
  provenance/      プロンプト・入力出力・参照ハッシュ・担当の記録
  registration.json
```

既存の `sources/v*`、`motions/v*`、`eyecatches/v*`、`animations/prime-v*` や作品名付きの版は、参照を保つためその場所で管理します。整理の都合で一斉に移動しません。採用・比較・再制作に使う元生成物を残し、コピー・派生の対応を記録します。比較・確認の終了後に使い道がなくなった旧媒体は、対応記録と旧SHAを残して削除します。

## 生成・編集の記録

### 必要な箇所だけ候補を作る

現行画像を見て、直すべき箇所と改善条件を先に決めます。原画の形が良好でも、前後姿勢と演技の軸がつながらず、意図したしぐさが伝わらない場合は修正対象になります。数値上の線幅差や、版番号が古いことだけを理由に一括再生成しません。

ラスタ原画のリメイクでは、採用通常姿を同一性・画風の参照にし、必要な姿勢を新しく描く案を用意します。前後の姿勢は演技と共通尺度の参照として役割を分けます。既存画像を部分編集する案も試せますが、元画の変形や描き直しのどちらが優れるかは実画像で比較します。どの方法でも原画へ上書きせず、良好な通常姿・ポーズ・clipを維持します。

### 保存する情報

各シートまたは単体画像に、実際に使った正確なプロンプトと次の来歴を保存します。

- 生成ツール、公開されている場合だけモデル識別子、透過の指定、実際の画像寸法・モード。
- 入力画像のプロジェクト相対パス、SHA-256、役割（同一性参照・画風参照・編集対象・合成要素）。参照系統の祖先と、その呼出しへ直接渡した入力を区別する。直接渡していない通常姿を、渡したと記録しない。
- 元の生成先と出力ハッシュ、プロジェクト内の保存先とハッシュ。過去の絶対パスは来歴として残せるが、再生・検証の必須入力は相対パスで解決する。
- 再生成・背景抽出・その他の編集では、比較・採用判断が済むまで前の画像を別案として保全し、編集対象・結果のハッシュと変更理由を残す。終了後、現在の利用・再制作・必要なQAに使わない旧画像は削除する。
- シートからの切り出しでは、元シートのハッシュ、行列数・並び、各セルの切り出し矩形、切り出したPNGのハッシュを残す。

新規原画、切り出し・変形などの派生、再利用、別名の状態を区別します。登録した状態数を、新規生成した独立原画の枚数として数えません。部品を編集・合成した場合も、入力画像、使った部位、マスク・変形・補間などの派生条件と実行コードを辿れるようにします。

`~/.codex/generated_images/`、一時フォルダ、チャット表示だけを唯一の保管先にしません。最終候補をプロジェクトへバイト一致で保存してから引き渡します。非公開のモデル名、失われたプロンプト・担当を推測して埋めず、欠落として管理して採用前に確認します。

## 画風と解像度の受入確認

### 画風と同一性

動物を同じ世界観へ増やす際は、次の2パターンを選び、採用元画像・用途・確認結果へ結び付けます。ハムスターと黄色い小鳥は例外的なデザインで、他の動物の標準には流用しません。

- 軽い擬人化：シャム猫・ハリネズミ・トラの採用通常姿を基準に、大きく丸い頭と短い胴、前肢を腕・手として使う構え、短い二足立ち、人らしい表情をそろえる。種の特徴を保ちながら、自然な四足姿を可愛く描いただけの案は採用しない。服・帽子の追加を擬人化の代用にしない。
- 鳥式の小物：ヤイロチョウの採用通常姿を基準に、丸い簡略形、単純な眼、大きい色面、茶色の輪郭と水彩の紙目をそろえる。鳥や擬人化が難しい水生動物などは背景に配置する小物として扱える。細かな羽片・皺・鱗・鰭条を積み重ねた図鑑的な自然画へ寄せず、想定する小さい表示でも種の色や形が読めるようにする。

`style_pattern` は `slightly-anthropomorphic-character` / `bird-like-prop`、用途は `cast-character` / `background-animal-prop` として登録できます。登録構造を分けず共通 `current/` で扱い、動きがなければ空のポーズ・clipを明示します。型の記載や透明度検査だけで画風合格にせず、原寸・明暗・最大使用サイズで基準画像と比較し、原画SHAと現在の `world_fit_review` へ結果を残します。基準に合わない自然体案の過去QAは保持し、現在の採用から外します。種類の特定が難しいものや、両パターンへ無理なくまとめられないものは理由を記録して見送れます。

基準は各キャラクターの採用通常姿です。採用済みのクマはシリーズの線の表現を確認する例として併用します。全員の線を任意の同一px値へ機械的に細く／太くしません。

通常姿と新しい全シート・全姿勢を同じ登録身体高で明色／暗色の背景へ合成し、輪郭の太さ・色、塗りの色味、紙目とぼかし、眼の形式、顔・耳・帽子・種固有の模様、頭身を比較します。視線・瞬き・表情の意図した変化と、目のハイライト追加などのデザイン変更を区別します。

自動測定の線幅比・色差は、目視確認が必要な箇所を探す補助です。閾値内だけで画風合格とせず、閾値外の枚数をそのまま不合格枚数にもしません。測定部位、表示尺度、透明度の閾値、測定の限界、比較画像と判断を残します。

頭の向きが変われば、眼の縦横比、顔の投影幅、帽子上面の見える面積も変わります。採用通常姿と姿勢の両方から説明できる投影か、別の顔・帽子へ変わったのかを判断します。全ポーズの顔幅や眼の形を機械的に一致させず、意図した投影差と作画の退行を記録します。

修正指摘はキャラ・シート・姿勢へ紐付け、以前の透過・画素一致の合格記録を保ちます。ファイル整合の合格だけで画風の指摘を解決済みにしません。過去の詳細監査は [管理記録と再検査](#管理記録と再検査) から辿れます。

仕上がりの再検査では、意図した紙目・柔らかな塗り・毛並み・種固有の斑と、汚れ・色の流れ込み・雑な二重線を分けます。判読できても拡大によって輪郭や眼の縁が柔らかくなる場合は、必要な姿勢だけ新規案を試せます。鮮明になっても、前後より濃く硬い線や淡く軽い面になって画調が変わる場合は退行として扱い、総合改善が明確でなければ既存を維持します。静止比較・GIFのデコード・実時間再生は確認範囲を区別して記録します。

### 実効解像度と使用倍率

作品で採用した出力解像度と使用サイズで、概ね高精細であることを受入条件にします。背景・キャラ・小物・教材図・貼り込み画像の使用範囲ごとに確認し、キャンバスやシート全体の寸法を一体あたりの実効解像度の代用にしません。

素材IDごとに、実描画または使用範囲の有効画素数、最大表示サイズ、ズーム・演技途中を含む最大拡大率を記録します。キャラは登録身体高も記録し、[身体基準と支点](#身体基準と支点)に従って校正します。原則として最大使用領域を十分に描ける素材を用意します。拡大が必要な場合は採用理由と原寸比較の合否を残し、シート内の描画が小さく輪郭・紙目がぼける場合は、単体または少ない姿勢での再生成を検討します。

### 表示品質の受入と記録

素材登録時は原寸プレビューで精細さを確認し、作品へ組み込む際は圧縮後の完成MP4を次の条件で検査します。

- 最大表示・ズーム・動作途中を含むフレームをデコードし、出力解像度の原寸・100%表示で輪郭・顔・目・模様・意図した質感、文字・数値の各桁を確認する。全画面と想定する縮小視聴サイズでも、教材に必要な情報を無理なく判別できることを確かめる。
- ぼけ・ジャギー・つぶれ・にじみ・細線の消失・圧縮ブロックが判別を妨げる場合は、素材の再生成、使用サイズ・構図、書き出し設定を見直して再確認する。水彩等の意図した柔らかさを保ち、機械的な拡大や輪郭強調だけで高精細と判定しない。1080p出力や大きな元画像を、実画の不足を見逃す理由にしない。

QAには素材IDと場面、上記の解像度情報、確認フレーム・表示倍率・原寸画像、合否と理由を残します。

## 透過・座標・動作の受入確認

### 透過と原画の保全

透過RGBAを保持し、明色と暗色へ合成して、背景の残り・にじみ・欠け・余分な部品を確認します。アルファ最大254やアルファ0内のRGBだけを不良理由にしません。原画への色抜き・輪郭の膨張収縮・アルファ清掃を、整理や登録の一部として実行しません。演技のための部品加工が必要な場合は、原画を保全した派生として、対象範囲と処理を記録します。

ごく低いアルファ値の微小点は、正しく合成した実画と最大表示サイズで可視の汚れになるかを確認します。値が存在することだけで一律に削除せず、主絵の欠け・切れ・背景残りと区別します。検出用のマスク処理を、原画のアルファ変更へ流用しません。

### 身体基準と支点

各シートで校正した身体基準高と、解剖上の足・腹等の支持点を登録します。同じシート内の全姿勢へ共通の等方縮尺を使い、しゃがみ・座位・下向き姿勢を個別のbbox高で拡大しません。複数シートは校正方法と数値を残します。オナガドリは身体と尾を別に扱い、尾幅で身体を縮めたり尾端を足支点にしたりしません。

共通縮尺は、同じ場面・表示尺度の動作群に適用します。場面別の配置・表示サイズ・移動は演出として設計し、原画の登録基準を保ったまま、場面ごとの縮尺・支点と遷移を検査します。

キャラクター間の場面上の身体高比は、原画の登録基準高とは別のメタデータで管理します。頭部だけのアイコンは全身ポーズと別の役割・可視範囲で登録し、足支点や身体基準高を付けません。座位の待機から操作反応へつなぐ場合は座位の前後姿勢を用意し、立位との急な切替を素材枚数だけで合格にしません。

空中画像では、次の方式を区別します。

- 描かれた足の解剖上の位置を支点とし、上下移動を作品側で加える。
- 周囲の接地姿勢から推定した地面を支点とし、原画に描かれた浮きを保つ。

支点の種類、推定／実測の別、推定元、作品側の移動方針を登録します。全素材の空中支点を一律に書き換えず、原画の浮きと作品側の跳躍を二重に加えません。くちばしを下げた絵だけで地面へ接触したと記録しません。

接地の登録では、解剖上の支点、両足の実接触領域の中心、足元の帯にある可視範囲の中央を区別します。帯の中央は姿勢・足の広がり・抽出範囲で変わり、登録支点と一致するとは限りません。支持点の意味と測定根拠を先に定め、観測する特徴点にずれがある場合はそのオフセットを保って射影します。透明余白や、曲げた姿勢の全高を新しい立位基準にしません。

### 動作の確認範囲

検査結果は、対象と観測方法を組にして記録します。

| 確認対象 | 判断できる範囲 |
|---|---|
| 原寸の静止原画 | 顔・手足・輪郭・透過・質感・単体の姿勢 |
| 同尺度の離散キーポーズ列・GIF | 姿勢の順序、投影・体格・支点・演技の意図のつながり。滑らかな補間は別検査 |
| 圧縮短片 | その背景・表示尺度・合成・書出し条件でデコードした実画と切替 |
| 完成作品 | 本編の実際の動作窓・教材・音声・字幕・場面遷移の成立 |
| 実時間の視聴・試聴 | 実際に連続再生して確認した区間のテンポ・動き・音。抽出静止画や全編デコードとは観測方法が異なる |

全編デコード、自動測定、時間順の抽出フレーム、連続再生の視認を分け、今回の対象SHA・実施件数・範囲・未確認条件を残します。過去の検査件数を今回の実施件数に足したり、静止や離散キーの合格を補間・完成作品へ転記したりしません。

開始・途中・保持・終了・ループ継ぎ目・通常姿への戻りで、足元、体格、道具の出入りを確認します。カップを持つループだけでは、作品内でのカップの登場・退場を確認したことになりません。

比較図・完成画面の配置と記録は [配置受入仕様](LAYOUT-ALIGNMENT.md) に従います。足支点合わせを意図した画像を、中央揃えの対象へ変えません。

### 演技の意図とポーズ列

顔や手足が整っていることと、意図したしぐさが伝わることを別に判断します。お辞儀の浅い姿勢から深い姿勢へ進む例では、頭・胴・視線の前傾が深まるか、途中で横傾きへ軸が変わっていないかを確認します。傾きの方向を単に大きくすれば演技が改善するとは限りません。

通常姿と前後姿勢を同じ校正済み尺度・支点で並べ、全身と顔の詳細を明暗で見ます。新しい投影・表情が意図に合い、同一性・体格・画風に退行がない場合だけ改善と判断します。静止画の魅力だけで一枚を選び、前後のつながりを省略しません。

### 腕・手などの部品演技

腕や手を動かす場合は、通常姿からの準備、上げ下げ、提示、保持、戻りを、場面に合う身体の動きとして設計します。キャラクターの種と画風に応じて、表現する関節・接続・意図した変形を定義します。一枚の下げ腕と手を付け根から大きく一体回転・拡大しただけで、自然な腕の演技ができたと判定しません。必要な曲げ姿勢・掌の向き・中間姿勢がなければ原画を追加します。回転角や原画枚数に共通の合格値を設けず、次の実画を確認します。

- 肩・上腕が胴へ自然につながり、表現する肘・前腕・手首の曲がりと掌の向きを読める。手の実寸と投影上の大きさ・厚さが動きに整合し、急な過大化・裏返り・潰れがない。
- 顔・頬・首と腕の前後関係が動作中も成立し、付け根が頬や首へ移ったように見えない。意図した接触・遮蔽は場面ごとに定義する。意図しない顔の上書き・頬への貼り付き、白い接合線や穴を残さない。
- 部品の外周・内部の指線・腕の内側線が意図した一組で続き、二重像・薄い残像・固定した旧腕・余分な手・途中消失がない。上げ終わりだけでなく、動き始めと戻り後半も確認する。
- 手だけを動かす設計では、採用通常姿の頭・胴・足と共通縮尺・足支点を保ち、全身で突発的な跳ね・大きさの変化・表情のちらつきがない。意図した頷き・屈伸・移動は、その動作と支点を別に検査する。通常姿との受け渡しと戻りを全身でも確認する。

変形用のケージやメッシュを使う場合は、肩・肘・手首・手先などの対応位置と輪郭の向きを揃えます。端点の絵が正常でも、反対向きの輪郭を補間すると途中で面積が潰れたり反転したりするため、途中形状・局所の厚み・欠けも検査します。向きが大きく変わる区間は、必要な中間原画や対応点を追加して再確認します。

二枚の絵を同じ外周へワープしても、内部の指線・内腕線の位置まで一致するとは限りません。線を含むテクスチャの混合やクロスフェードは、薄い二組の線を生む場合があります。輪郭と内部線の対応付け、線を分離した派生の塗りと一組の線の描画、中間原画など、素材に合う方法で解消します。特定の手法を一律に義務化せず、原画の画風を保ち、全区間で意図した線が一組に見える結果を受け入れます。派生処理を原画へ上書きしません。

### 本編前の圧縮短片

新作・動作品質の改訂では、本編の長時間書き出し前に、採用する全動作種を含む圧縮短片を作り、実画で受け入れます。本編で使う解像度・背景・表示尺度・合成・補間と書き出し条件を反映し、左右差、両手、最大表示、場面切替など、形や見え方が変わる条件を含めます。

短片のMP4を実際にデコードし、原寸の時間順フレームと連続動作で、準備から戻りまでを確認します。腕の拡大診断だけで済ませず、顔や全身との関係も確認します。切り出し範囲の外へ移ったキャラや予定した全画面フェードを、腕の消失と取り違えません。過去の実MP4との比較も同じ表示尺度で行います。

短片のSHA-256、入力画像・登録・実行コードのSHA-256、確認した動作種・区間・表示倍率・方法、合否・未確認範囲を残します。不合格箇所は修正後の新しい短片の同区間と前後で再確認し、不合格記録と当時のパス・SHAを残します。旧短片は現在の比較・回帰検査に必要な場合だけ保持し、用済みになったものは削除します。技術的なハッシュ一致や動作量の測定だけで、演技の自然さを合格にしません。

短片の合格はその入力・表示条件・確認範囲に限ります。本編は一致する入力で書き出した後、完成MP4を新たにデコードし、採用された全動作区間と場面別の見え方を検査します。短片の結果を完成MP4の実視認として転記せず、実時間再生・連続フレーム・標本抽出・自動測定を区別して記録します。完成作品の教材・音声・字幕等の検査は [制作仕様](PRODUCTION.md) に従います。

## リメイク候補をユーザーに提示する

### 比較設定と準備

修正対象は [必要な箇所だけ候補を作る](#必要な箇所だけ候補を作る) に従って絞ります。比較前に既存の原画・登録・SHAを固定します。

リメイク案の比較には [`tools/image_remake_review.py`](../tools/image_remake_review.py) を使います。前バージョンと候補を同じ画面へ出し、**「前バージョン」「AIおすすめ」を選択前から文字付きの印で表示**します。AIのおすすめをユーザーの選択として扱わず、初期状態は未選択にします。2案にも、前バージョンを含む複数案にも使えます。

おすすめは比較結果から決め、既存版を `recommended_variant_id` に指定しても構いません。新規案であることだけを理由におすすめへせず、下のJSON例の指定も採用判断とは分けます。

入力JSONに `id`、`title`、`previous_variant_id`、`recommended_variant_id`、`variants` を指定します。各案は `id`、`label`、プロジェクト相対の `path` を持ちます。キャラクターの同尺度比較では、登録・校正の記録から各案の `reference_height_px`、`anchor_px`、`body_bbox_px` を渡します。透明余白やキャンバス全体を身体基準の代わりにせず、案ごとの個別fitで大きさを揃えません。未登録画像では可視範囲から静止画比較用の基準を作り、身体登録と区別します。

比較対象の `path` には固定した原画か比較専用の無改変コピーを指定します。採用切替で内容が変わる `current/` を前バージョンの唯一の入力にせず、`asset.json` の `source_path` 等から元原画を辿ります。すでに可変パスを使った設定は保全し、元画像のSHA一致を確認した固定パスで別の比較設定を準備します。比較中は固定した入力で判断し、正式採用後も当時の比較設定・選択・SHAの記録を保持します。用済みの比較画像は整理対象とし、削除した場合は記録で提供状況を示します。

2枚を比べる最小設定は次の形です。ID・名前・画像パスは、プロジェクト内の実体へ置き換えます。

```json
{
  "schema_version": 1,
  "id": "image-remake-v001",
  "title": "リメイク画像を選ぶ",
  "previous_variant_id": "previous",
  "recommended_variant_id": "remake",
  "variants": [
    {"id": "previous", "label": "前バージョン", "path": "assets/previous.png"},
    {"id": "remake", "label": "リメイク案", "path": "assets/remake.png"}
  ]
}
```

入力設定と出力先を新規に用意し、画像パス・ラベル・前版・おすすめを手元の実体へ置き換えます。下のパスとポートは例です。使用中の出力先・ポートを再利用せず、準備時に固定した画像のSHA-256と寸法を保ちます。既に出力済みの比較設定へ上書きしません。

```sh
.venv/bin/python tools/image_remake_review.py prepare --spec design/image-remake-reviews/my-remake-v001/spec.json --output design/image-remake-reviews/my-remake-v001/review.json
.venv/bin/python tools/image_remake_review.py serve --review design/image-remake-reviews/my-remake-v001/review.json --port 8790
```

### 表示と選択の検査

比較プレビューは原画を書き換えない診断表示です。`preview_geometry` の実アルファ可視範囲と足支点近傍の実描画検査で、両軸の差・収まり・切れを確認します。座標変換の一致だけで配置合格にしません。補間で生じる微小な描画ずれは、固定した元画像の可視特徴の射影位置へ表示だけを最大1.5px補正し、補正前後の両軸差を `placement_calibration` へ記録します。元画像・尺度・登録支点・基準領域・許容差は変えず、大きなずれを無制限に補正しません。空中姿勢は描かれた足と推定地面を分け、その距離を保って実描画を測ります。小さな原画の大幅拡大等で実描画の差が許容範囲を超えた場合は、不合格を隠さず画像・登録・表示尺度を見直します。

上記1.5pxは比較ツールの表示校正の実装上限で、原画の位置誤差や他の観測器へ共通の許容差を追加する値ではありません。描画倍率・背景・観測器が異なる条件はそれぞれ検査し、ある倍率の成功で別倍率の失敗を消しません。原画と観測器の不備の切り分けは [配置仕様](LAYOUT-ALIGNMENT.md#完成映像の前景抽出と誤検出の切り分け) に従います。

表示されたローカルURLを開き、画像を並べて選びます。前バージョンの維持と保留も記録できます。選択を比較設定と画像のSHAに結び付け、設定の隣の `decisions/` へ履歴として保存します。再選択で前の記録を消さず、画像・設定が変わった古い画面からの選択を受け付けません。

選択操作はユーザーへ渡すブラウザでも実際に確認します。画面を開いたままサーバーが再起動した場合も、保存直前に同一の比較設定・画像SHAを照合して接続情報を更新します。保存中・成功・失敗は押したボタンの近くに表示し、画面上部の通知だけで完了を伝えません。検証用の選択は専用設定へ保存し、ユーザーの実際の選択履歴に混ぜません。

```sh
.venv/bin/python tools/image_remake_review.py show --review design/image-remake-reviews/my-remake-v001/review.json
```

### 複数ポーズの比較一覧

ポーズごとに別の比較設定を準備し、`schema_version: 1`、`id`、`title`、`reviews` を持つ一覧JSONへまとめます。`reviews` の各項目には、比較設定と一致する `id`、レビューJSONへのプロジェクトルート相対パス `review`、任意の `group` を指定します。下の一覧も新規に作成するパスの例です。一覧を一つのサーバーで開けます。

```sh
.venv/bin/python tools/image_remake_review.py serve --collection design/image-remake-reviews/my-poses-v001/collection.json --port 8791
```

一覧からポーズを開き、前バージョンと再生成版を比べます。選択履歴は各比較設定の隣へ分けて保存し、一つのポーズの選択を他へ適用しません。一覧へ戻って次を確認できます。全ポーズを一つの比較の `variants` へ詰めて、全体から一枚だけを選ぶ設定にはしません。

<a name="通常姿と汎用姿勢の明示採用"></a>

### 選択から採用への反映

新規案は既存と同じ校正済み尺度で明色・暗色背景と原寸表示を比較し、ポーズ素材は前後の姿勢とのつながりも確認します。改善が明確で、同一性・画風・体格・支点・動作・精細さ等に退行がないときだけ差し替えます。同程度・判断不明・悪化なら既存を維持し、対象の欠点・改善条件・比較条件・判定根拠と新旧両方のSHA-256を記録します。

ユーザーが選ぶ場合は、その選択前に採用済みと記録しません。比較ツール自体は既存の採用素材を書き換えません。選択結果と、登録・共通縮尺・QAを揃えた正式な採用を区別します。採用前の候補や個人の選択記録を公開用の素材一覧へ自動追加しません。

品質確認後におすすめ案を採用するようユーザーから委任された場合は、その指示・比較条件・確認結果を採用根拠へ記録します。管理上の判断をユーザーのクリック履歴として記録せず、テスト用操作も実際のユーザー選択へ混ぜません。

通常姿・短い演出を明示採用するときは、次の順で進めます。

1. 原画・入力・QAを確定し、作業領域で採用記録案を用意する。`catalogs/character-adoptions-v1.json` の `adoptions` へ反映する対象ID・`status: adopted`・通常姿のパス/SHA/座標・短い演出の登録/SHA・非空の `selection_evidence` を明示し、この段階では共有台帳を更新しない。
2. 一部の姿勢だけを替える場合は、良好な姿勢を固定した元パス・SHA・登録で再利用する。新しいセットの版数へ揃えるためだけに、全PNGを複製・再生成しない。必要な既存の選択根拠を保ち、新しい根拠を追加する。
3. 直前の台帳・登録・`current/` の画像とメタデータを保全し、変更対象外の画像・登録・clipをハッシュと意味内容で照合できる状態にする。
4. 採用台帳を更新し、`character_library.py refresh` でINDEXを再構築する。異なるPNGへの上書きを拒否する共通ビルダーの保護を回避せず、更新対象の旧ビューを記録付きで退避して `unified_asset_library.py build`・`verify` で作り直す。
5. 必要な在庫・ファイル一覧を更新し、[全体検査](#在庫の更新と全体検査)を実行する。別素材の `asset.json` にある参照INDEXのSHAだけが変わる場合も、画像の変更と区別して理由を記録する。

過去の採用・collection・QAの記録は保持し、旧画像や旧動画は現在の利用・再制作・必要なQAに使うものだけを残します。共有素材の採用だけで、既存作品の採用先や完成動画を変更しません。利用ガイドは全IDを同じ `current/` の入口で案内し、新旧・追加時期で別の素材群へ分割しません。

名前空間内の一部だけを明示差し替えする場合は、採用台帳の `pose_set_overrides` に元登録のパス・SHA、置換前PNGのパス・SHA、新しい部分登録を固定します。置換対象のID集合を完全一致で検査し、他ポーズの原画・尺度・支点とclipを保持します。追加の任意ポーズも一体ずつ腕・脚・尾の接続を原寸と前後姿勢で確認し、一覧の縮小表示や以前の合格だけで採用しません。

## 台帳の更新と公開

### 排他と更新前の照合

管理担当は更新前の台帳・設定のSHA-256を読み、書き込み直前に同じ内容であることを確認します。別作業の更新があれば最新状態を読み直し、差分を再適用します。古いJSONを丸ごと書き戻しません。共有台帳の更新は直列に行い、排他的な担当予約と楽観的なハッシュ照合を併用します。

管理ツールは、設定の予約・解放と在庫公開に同じ設定ファイルのロックを使います。公開時は設定・在庫・人向け一覧のロックを保持して最終照合と置換を行い、途中に予約だけが成功して古い在庫を完了扱いにすることを防ぎます。人向け一覧の固定公開先と親ディレクトリにはシンボリックリンクを使いません。

生成中の範囲は保存先のパスで枝ごと除外し、その中の入力参照リンクも確定在庫へ取り込みません。予約範囲は大文字・小文字の違いも同じ領域とみなし、実パス解決やファイル情報の取得より前に除外します。

汎用ライブラリの `character_library.py refresh` も同じ予約設定のロックを使います。採用INDEXとファイル一覧の開始時SHA、原本の二重走査、書き込み直前の一致を確認し、ポーズ名・登録ID・画像パス・シートIDを照合します。画像のハッシュが正しくても、別の動作名で選ばれる対応は拒否します。

### 確定・公開・採用の順序

画像と来歴を先に確定し、登録・選択根拠、採用台帳、派生ビュー、ファイル一覧の順に整合を確かめます。collectionによる採用では該当manifestも確認しますが、過去のcollectionを書き換えて新しい明示採用を選ばせません。各JSONは同じファイルシステム内の一時ファイルへ書いて置換します。複数ファイルが一度に更新できると仮定せず、更新中の記録と完了時のハッシュを残します。途中失敗時は実際の台帳・画像・差分を調べ、既に反映された範囲と未反映の範囲を分けて復旧します。

収録だけで `active_production_set_ids`、作品の動作入力、通常姿、汎用ポーズの選択を変更しません。新しい共有素材は明示的な名前空間・セットIDから利用します。`expanded/` と `eyecatch/`、作品用の `prime-*`／`fibonacci-*` は別の用途です。汎用ローダーへ未登録でも、作品側で採用されている素材を未採用と決め付けません。

採用範囲を更新するときは、選択した登録情報・SHA-256・検査範囲・参照元・作品の根拠を記載します。静止画確認だけで動作確認済みにしません。新しい汎用素材の追加だけで、既存ポーズのパスや共通基準高を変えません。

共通素材・カタログの更新後は、[管理コマンド](#管理コマンドと引き継ぎ)にある全体検査まで実行します。生成中と明示された来歴の欠落、構造エラー、画風・完成作品の品質を分けて報告します。

## 不整合・重複・中断時の整理

- 未登録画像は、生成バッチ・来歴・作品からの参照を調べる。用途が未確定なら未分類または候補として登録し、最大版数や更新時刻で採用しない。
- 書き込み中の画像増減や読み取り前後のハッシュ変化は、在庫検査の失敗または保留として扱う。生成担当の完了後に再検査し、不安定な一回の観測を完全な在庫として記録しない。
- 既存ファイルのハッシュ不一致は、実体・元シート・切り出し・来歴を調べる。検証を通すために期待ハッシュを現物へ置き換えない。新規追加で一覧が古い場合は、追加内容を分類してから管理用一覧を再構築する。
- 同一SHA-256の重複は、同じ内容の別名として記録できる。来歴や参照元が異なる場合があるため、勝手に削除・置換・リンク化しない。
- 中断した予約は日時だけで期限切れと決めない。所有者・実行状態・保存中のファイルを確認し、引き継ぐ担当と記録を残してから解除する。
- 不採用案は理由と来歴を記録し、比較・採用判断の終了後、現在の利用・再制作・必要なQAに使わない旧媒体は容量整理の対象とする。制作中の素材は他担当が削除せず、用途未確定の旧版は担当・実際の参照・稼働状態を調べて用途を確定する。

この仕様は追加のユーザー承認手順を設けません。依頼された管理・分類・検査と、明示的に依頼された採用変更を、それぞれの範囲で進めます。

## 管理コマンドと引き継ぎ

リポジトリのルートで実行します。本PCは `.venv/bin/python` を使い、別環境では準備済みのPythonへ読み替えます。

### 読み取り確認と担当予約

```bash
.venv/bin/python tools/manage_character_assets.py inspect
.venv/bin/python tools/manage_character_assets.py check
.venv/bin/python tools/character_library.py verify
.venv/bin/python tools/unified_asset_library.py verify
```

予約・解放には、衝突しない保存先と所有者を指定します。

```bash
.venv/bin/python tools/manage_character_assets.py reserve --batch-root assets/library/characters/kangaroo/generation-batches/task-a-f83c --owner ai-a --id task-a-f83c
.venv/bin/python tools/manage_character_assets.py release --reservation-id task-a-f83c --owner ai-a
```

別所有者による予約範囲の重複確保と解放は拒否します。生成中の範囲は確定ハッシュの計算から除外し、`pending` として残します。既に採用・在庫登録されたファイルを予約で隠してハッシュ確認を免除しません。

### 在庫の更新と全体検査

管理担当は未分類の来歴・参照・品質を確かめて設定へ追記し、完了した範囲の在庫を再構築します。`refresh` は画像を移動せず、管理在庫と人向け一覧を更新します。直前に読み取った在庫SHA-256を `--expected-registry-sha256` へ指定すると、前提とする状態を明示できます。

```bash
.venv/bin/python tools/manage_character_assets.py refresh --expected-registry-sha256 HASH_FROM_LAST_READ
.venv/bin/python tools/manage_character_assets.py check
.venv/bin/python tools/verify_workspace.py
```

汎用ライブラリの一覧が追加素材により古くなった場合は、分類・来歴・安定した実体を確認した後、管理担当だけが `tools/character_library.py refresh` を実行して `verify` し、全体検査を行います。共通ビューを更新した場合は `tools/unified_asset_library.py verify` も実行します。生成中の未完了バッチを完了素材と分け、登録済みファイルの変更は新規追加と区別して原因を調べます。画像だけ取得した利用者へ、ローカル動画や全保管履歴を要求する制作原本向け検査を課しません。

### 不要旧版を削除する場合

容量整理では、明らかに再生成できる大容量動画と、用済みの旧build・検証コピー・cacheを優先して削除します。原画・採用入力・現在必要なQAを保護し、旧媒体を一律に保管し続けることはしません。小さい素材の用途細分化のために制作やGitHub更新を長時間止めず、判断が曖昧なものは保持して更新を進めます。

版番号や日付だけで削除を決めず、制作原本とGitHub公開版それぞれの採用先、原画・登録、renderer/import、実際に使う比較基準、現在の品質・音声検査の入力・根拠を確認します。旧名でも現在必要な実体は残します。過去のパス・SHAの記載、旧在庫への収録、かつて採用されたことだけでは、媒体の現在の用途とはみなしません。

削除するファイルをパス・SHA-256・byte数・理由で固定し、残す同一原画があれば対応先を記録します。生成中の他担当領域には触れず、用途未確定の旧版は担当・実際の参照・稼働状態を調べて用途を確定します。実行直前に実体と用途・参照の変更を再照合して、列挙したファイルだけを削除します。使い道のない完了済み検証コピー・旧試写・比較画像も削除し、当時の入力・判断・検査記録と分けて管理します。

過去の採用・比較・検査JSONは当時の記録として残し、削除した旧媒体の提供状況は管理設定の `retirement_records` に記録します。過去のパスや期待SHAを現存する別ファイルへ書き換えて欠落を隠しません。在庫・人向け一覧・公開profileと実体のハッシュ一覧を更新し、採用画像と制作依存が変わっていないことを検査します。GitHubへの反映は通常の削除commitとし、履歴の書換えは別の明示指示がある場合に限ります。

## 管理記録と再検査

現在の担当・分類・品質は管理設定と管理一覧を参照します。初回整理、作品ごとの引き継ぎ、独立再検査、旧出力から保全先への対応は、[管理記録の入口](../assets/library/collections/character-management/v001/manifest.json)へまとめています。過去の記録の日時と検査範囲を保ち、個別作業の経過を本仕様へ重複記載しません。

過去の画風監査は [`character-style-audit/v001/index.html`](../assets/library/collections/character-style-audit/v001/index.html) と同フォルダの `audit-summary.json` から辿れます。当時の診断97ファイルはこの保全先へ統一され、manifestに旧出力パス・保全先・ハッシュを記録しています。内容一致を確認した二重保管分の削除は当時の整理記録で、今後の原画を自動削除する規則ではありません。

部分リメイクの事例は、クマの [明示採用と比較根拠](../assets/library/characters/bear-beret/eyecatches/v003/selection.json)、[静止比較](../assets/library/characters/bear-beret/eyecatches/v003/qa/bow-deep-v001-static-comparison-final.json)、[限定した圧縮確認](../assets/library/characters/bear-beret/eyecatches/v003/qa/bow-deep-v001-compressed-review-final.json)です。一姿勢の演技を改善して他の良好な姿勢を再利用した記録として読み、同作品の身体高・画素位置・検査件数を共通の合格値にしません。最新の採用先は版番号で選ばず、採用台帳から確認します。

腕の受入条件の実例は、等差数列の不自然な一体回転の確認（制作原本の参考資料・公開版には未同梱: `design/arithmetic-sequence-counting-v1/arm-motion-review-20261113-v001/root/confirmed-defect-v001.json`）、線の二重化で不合格となった短片（制作原本の参考資料・公開版には未同梱: `design/arithmetic-sequence-counting-v1/arm-motion-review-20261113-v001/independent/preview-gate-v001.json`）、修正後の短片（制作原本の参考資料・公開版には未同梱: `design/arithmetic-sequence-counting-v1/arm-motion-review-20261113-v001/independent/preview-gate-v002.json`）、完成MP4の別検査（制作原本の参考資料・公開版には未同梱: `design/arithmetic-sequence-counting-v1/arm-motion-review-20261113-v001/video/final-v007-artistic.json`）を参照します。部品演技の実装例（制作原本の参考資料・公開版には未同梱: `tools/arithmetic_animation_v003.py`）は一つの方法であり、同作品の角度・原画数・フレーム数・表示サイズ・測定閾値を他作品の共通合格値へ転用しません。

画風の自動測定を再実行する場合は、`tools/audit_character_style.py --output <未使用の診断出力先>` を明示し、保全済みの監査先へ出力しません。
