# 画像素材の管理・並行生成仕様

この仕様は、複数のAIや作業者が同時に生成するキャラクター画像を、原画・候補・採用版・作品別素材として追跡するための規約です。管理のための整理と、新しい素材の採用を分けます。整理だけで既存動画の見た目や採用先を変えません。

## 正本と管理する情報

通常姿・汎用動作の実利用は [`catalogs/character-library-v1.json`](../catalogs/character-library-v1.json)、作品固有の採用先は [`catalogs/library-v1.json`](../catalogs/library-v1.json) と作品の制作記録から辿ります。管理用の一覧は生成バッチ全体を把握するために使い、未分類・未採用の画像も記載します。一覧へ収録されたこと、ハッシュが一致したこと、ファイル名に `v003` 等が付いていることは、採用や画風合格を意味しません。

管理設定は [`catalogs/character-asset-management-v1.json`](../catalogs/character-asset-management-v1.json)、そこから作る在庫は [`catalogs/character-asset-registry-v1.json`](../catalogs/character-asset-registry-v1.json) です。更新・検査には [`tools/manage_character_assets.py`](../tools/manage_character_assets.py) を使います。設定の各 `batches` は `root`、担当 `owner`、用途 `scope`、分類 `state`、`registration_paths`、`selection_evidence`、`quality_reviews` を明示します。分類の不明な新規バッチは `unclassified` のまま追跡します。

次の情報を混同しません。

| 情報 | 記録する内容 |
|---|---|
| 来歴 | 作業ID・所有者、生成／編集日時、正確な指示文、入力と出力、SHA-256 |
| 作業履歴・品質 | 生成中、受領済み、候補、静止画確認、動作確認、採用、要修正、保管を根拠付きで記録 |
| 採用範囲 | 通常姿、共有ストック、特定作品用、制作準備用、未採用 |
| 検査 | ファイル整合、画素由来、静止画の品質、画風、動作、完成作品の検査を個別に記録 |

検査上の `needs_revision` と、過去の作品で選択された事実は共存できます。過去の採用履歴や当時の検査記録を消して、現在の判定へ書き換えません。

管理設定の `state` は `canonical`、`shared_stock`、`episode_selected`、`preproduction`、`candidate`、`archive`、`unclassified` の用途分類です。生成中かどうかは `reservations` の所有者と `active`／`released`、品質は `quality_reviews` で別に管理します。

## 並行作業の担当と保存先

1. 生成開始前に、キャラクター・用途・作業ID・担当AI／作業者・保存先を予約します。作業IDには日時だけでなくタスク識別子と衝突しない識別子を含めます。別のAIが同じ `motions/v002` 等を独立に確保してはいけません。
2. 生成担当は自分のバッチ内だけへ書き込みます。共通台帳、採用先、ファイル一覧の更新は管理担当一人に集約します。同じAIが複数役割を担っても、書き込みの順序は直列にします。
3. 生成中の予約があるバッチは、他の担当が移動・削除・改名・上書きしません。管理側では生成中として追跡し、未完了のファイル集合を確定済みの在庫として扱いません。
4. 所有者が完了を宣言し、画像と来歴の保存・検査が終わってから管理へ引き渡します。確認後の追記も担当と内容を記録し、登録中に無断で支点や画像を更新しません。

新規作業は、例えば次のように衝突しないバッチへまとめます。

```text
assets/library/characters/<character-id>/generation-batches/<unique-batch-id>/
  source/          元生成画像・元編集画像の無改変コピー
  candidates/      不採用案・再生成前の案・却下理由
  frames/          採用候補の無損失セル抽出等
  previews/        明暗比較・拡大図・動作確認用GIF
  provenance/     プロンプト・入力出力・参照ハッシュ・担当の記録
  registration.json
```

既存の `sources/v*`、`motions/v*`、`eyecatches/v*`、`animations/prime-v*` や作品名付きの版は、参照を保つためその場所で管理します。整理の都合で一斉に移動しません。新しい採用版へ収納するときも元生成物を残し、コピーまたは派生の対応を記録します。

## 生成・編集の記録

各シートまたは単体画像には、対応する正確なプロンプトと来歴を保存します。

- 実際に使った生成ツール、公開されている場合だけモデル識別子、透過の指定、実際の画像寸法・モード。
- 入力画像のプロジェクト相対パス、SHA-256、役割（同一性参照・画風参照・編集対象・合成要素）。
- 参照系統の祖先と、その呼出しへ直接渡した入力を区別する情報。直接渡していない通常姿を、渡したと記録しません。
- 元の生成先と出力ハッシュ、プロジェクト内の保存先とハッシュ。過去の絶対パスは来歴として残せますが、再生・検証の必須入力は相対パスで解決します。
- 再生成・背景抽出・その他の編集は、前の画像を別案として保全し、編集対象と結果のハッシュ、変更理由を残します。
- シートから切り出す場合は、元シートのハッシュ、行列数・並び、各セルの切り出し矩形、切り出したPNGのハッシュを残します。

`~/.codex/generated_images/`、一時フォルダ、チャットに表示された画像だけを唯一の保管先にしません。最終候補をプロジェクトへバイト一致で保存してから引き渡します。ツールが公開していないモデル名や、失われたプロンプト・担当を推測して埋めません。欠落は欠落として管理し、採用前に確認します。

## 画風と解像度の受入確認

### 画風と同一性

基準は各キャラクターの採用通常姿です。採用済みのクマはシリーズの線の表現を確認する例として併用します。全員の線を同じ任意のpx値へ機械的に細く／太くしません。

同じ登録身体高で、通常姿と新しい全シート・全姿勢を明色／暗色の背景へ合成して比較します。輪郭の太さ・色、塗りの色味、紙目とぼかし、眼の形式、顔・耳・帽子・種固有の模様、頭身を確認します。視線・瞬き・表情による意図した変化と、目のハイライト追加などのデザイン変更を区別します。

自動的な線幅比・色差は、目視確認が必要な箇所を探す補助です。閾値内だけで画風合格とせず、閾値外の枚数をそのまま不合格枚数にもしません。測定する部位、表示尺度、透明度の閾値、測定上の限界、比較画像と判断を残します。

現在の詳細監査は、保全した [`assets/library/collections/character-style-audit/v001/index.html`](../assets/library/collections/character-style-audit/v001/index.html) と同フォルダの `audit-summary.json` が入口です。診断97ファイルの正本はこの保全先に統一しました。manifestで旧出力パス・保全先・ハッシュを対応付け、内容一致を確認した二重保管分は削除しています。修正指摘は対象のキャラ・シート・姿勢へ紐付けて管理し、以前の「透過／画素一致が合格」という記録を消しません。ファイル整合の合格だけで画風の指摘を解決済みにしません。

### 実効解像度と使用倍率

YouTube向けの画像は、作品で採用した出力解像度と使用サイズで概ね高精細であることを受入条件にします。背景・キャラ・小物・教材図・貼り込み画像の使用範囲ごとに確認し、キャンバスやシート全体の寸法を一体あたりの実効解像度の代用にしません。

素材IDごとに実描画または使用範囲の有効画素数、最大表示サイズ、ズーム・演技途中を含む最大拡大率を記録します。キャラでは登録身体高も記録し、身体基準・支点の校正は「透過・座標・動作の受入確認」に従います。原則として最大使用領域を十分に描ける素材を用意し、拡大が必要な場合は採用理由と原寸比較の合否を残します。シート内の描画が小さく、輪郭や紙目がぼける場合は、単体または少ない姿勢での再生成を検討します。

### 表示品質の受入と記録

素材登録時は原寸プレビューで精細さを確認し、作品へ組み込む際は次の条件で完成MP4を検査します。

- 最大表示・ズーム・動作途中を含むフレームをデコードし、出力解像度の原寸・100%表示で輪郭・顔・目・模様・意図した質感と、文字・数値の各桁を確認する。全画面と想定する縮小視聴サイズでも、教材として必要な情報を無理なく判別できることを確かめる。
- ぼけ・ジャギー・つぶれ・にじみ・細線の消失・圧縮ブロックが判別を妨げる場合は、素材の再生成、使用サイズ・構図、書き出し設定を見直して再確認する。水彩等の意図した柔らかさは保ち、機械的な拡大や輪郭強調だけで高精細になったと判定しない。出力が1080pであることや元画像の解像度を、画質の不足を見逃す理由にしない。

QAには素材IDと場面、使用した上記の解像度情報、確認フレーム・表示倍率・原寸画像、合否と理由を残します。

## 透過・座標・動作の受入確認

透過RGBAを保持し、明色と暗色へ正しく合成して、背景の残り・にじみ・欠け・余分な部品を確認します。アルファ最大254やアルファ0内のRGBだけを不良理由にしません。原画への色抜き・輪郭の膨張収縮・アルファ清掃を、整理や登録の一部として実行しません。

各シートで校正した身体基準高と、解剖上の足・腹等の支持点を登録します。同じシート内の全姿勢へ共通の等方縮尺を使い、しゃがみ・座位・下向き姿勢を個別のbbox高で拡大しません。複数シートは校正の方法と数値を残します。オナガドリは身体と尾を別に扱い、尾幅で身体を縮めたり尾端を足支点にしたりしません。

空中画像では、次の二つを必ず区別します。

- 描かれた足の解剖上の位置を支点とし、上下移動を作品側で加える方式。
- 周囲の接地姿勢から推定した地面を支点とし、原画に描かれた浮きを保つ方式。

登録には支点の種類、推定／実測の別、推定元、作品側の移動方針を残します。全素材の空中支点を一律に書き換えず、原画の浮きと作品側の跳躍を二重に加えません。くちばしを下げた絵だけで地面へ接触したと記録しません。

動作確認は開始・途中・終了・ループ継ぎ目・通常姿への戻り、足元、体格、道具の出入りを確認します。GIFが離散キーポーズの一覧なら、その範囲を明記します。補間・発話同期・動作頻度・画面内の余白まで確認した完成作品の検査と分けます。紅茶のカップを持つループには、作品側でのカップの登場・退場が別途必要です。

比較図・完成画面の配置確認と記録は [配置受入仕様](LAYOUT-ALIGNMENT.md) に従います。足支点合わせを意図した画像を、中央揃えの対象へ変えません。

## リメイク候補をユーザーに提示する

### 比較設定と準備

リメイク案の比較には [`tools/image_remake_review.py`](../tools/image_remake_review.py) を使います。前バージョンと候補を同じ画面へ出し、**「前バージョン」「AIおすすめ」を選択前から文字付きの印で表示**します。AIのおすすめをユーザーの選択として扱わず、初期状態は未選択にします。2案にも、前バージョンを含む複数案にも使えます。

入力JSONに `id`、`title`、`previous_variant_id`、`recommended_variant_id`、`variants` を指定します。各案は `id`、`label`、プロジェクト相対の `path` を持ちます。キャラクターの同尺度比較では、登録・校正の記録から各案の `reference_height_px`、`anchor_px`、`body_bbox_px` を渡します。透明余白やキャンバス全体を身体基準の代わりにせず、案ごとの個別fitで大きさを揃えません。未登録画像では可視範囲から静止画比較用の基準を作り、身体登録と区別します。

比較対象の `path` には固定した原画か比較専用の無改変コピーを指定します。採用切替で内容が変わる `current/` を前バージョンの唯一の入力にせず、`asset.json` の `source_path` 等から元原画を辿ります。すでに可変パスを使った設定は保全し、元画像のSHA一致を確認した固定パスで別の比較設定を準備します。これにより正式採用後も同じ画像で比較履歴を読めます。

2枚を比べる最小設定は次の形です。ID・名前・画像パスは、プロジェクト内の実体へ置き換えます。

```json
{
  "schema_version": 1,
  "id": "image-remake-v001",
  "title": "リメイク画像を選ぶ",
  "previous_variant_id": "previous",
  "recommended_variant_id": "remake",
  "variants": [
    {"id": "previous", "label": "前バージョン", "path": "assets/previous.png"},
    {"id": "remake", "label": "リメイク案", "path": "assets/remake.png"}
  ]
}
```

制作原本の実例 `design/image-remake-reviews/bear-outline5-v001/spec.json` は、この公開版には収録していません。公開版から利用する場合は、上の最小設定をこのパス例などへ新規保存し、画像パス・ラベル・前版・おすすめを手元の実体へ置き換えます。下のコマンドはその設定を保存してから実行します。準備時に画像のSHA-256と寸法を固定し、出力済みの比較設定へ上書きしません。

```sh
.venv/bin/python tools/image_remake_review.py prepare --spec design/image-remake-reviews/bear-outline5-v001/spec.json --output design/image-remake-reviews/bear-outline5-v001/review.json
.venv/bin/python tools/image_remake_review.py serve --review design/image-remake-reviews/bear-outline5-v001/review.json --port 8767
```

### 表示と選択の検査

比較プレビューは原画を書き換えない診断表示です。`preview_geometry` の実アルファ可視範囲と足支点近傍の実描画検査で、両軸の差・収まり・切れを確認します。座標変換の一致だけで配置合格にしません。補間で生じる微小な描画ずれは、固定した元画像の可視特徴の射影位置へ表示だけを最大1.5px補正し、補正前後の両軸差を `placement_calibration` へ記録します。元画像・尺度・登録支点・基準領域・許容差は変えず、大きなずれを無制限に補正しません。空中姿勢は描かれた足と推定地面を分け、その距離を保って実描画を測ります。小さな原画の大幅拡大等で実描画の差が許容範囲を超えた場合は、不合格を隠さず画像・登録・表示尺度を見直します。

表示されたローカルURLを開き、画像を並べて選びます。前バージョンの維持と保留も記録できます。選択を比較設定と画像のSHAに結び付け、設定の隣の `decisions/` へ履歴として保存します。再選択で前の記録を消さず、画像・設定が変わった古い画面からの選択を受け付けません。

選択操作はユーザーへ渡すブラウザでも実際に確認します。画面を開いたままサーバーが再起動した場合も、保存直前に同一の比較設定・画像SHAを照合して接続情報を更新します。保存中・成功・失敗は押したボタンの近くに表示し、画面上部の通知だけで完了を伝えません。検証用の選択は専用設定へ保存し、ユーザーの実際の選択履歴に混ぜません。

```sh
.venv/bin/python tools/image_remake_review.py show --review design/image-remake-reviews/bear-outline5-v001/review.json
```

### 複数ポーズの比較一覧

ポーズごとに別の比較設定を準備し、`schema_version: 1`、`id`、`title`、`reviews` を持つ一覧JSONへまとめます。`reviews` の各項目には、比較設定と一致する `id`、その `review` 相対パス、任意の `group` を指定します。一覧を一つのサーバーで開けます。下の `collection-current.json` は新規に作成する一覧のパス例で、制作原本の比較設定・候補画像・選択履歴はこの公開版には同梱していません。

```sh
.venv/bin/python tools/image_remake_review.py serve --collection design/image-remake-reviews/bear-poses-outline5-v001/collection-current.json --port 8780
```

一覧からポーズを開き、前バージョンと再生成版を比べます。選択履歴は各比較設定の隣へ分けて保存し、一つのポーズの選択を他へ適用しません。一覧へ戻って次を確認できます。全ポーズを一つの比較の `variants` へ詰めて、全体から一枚だけを選ぶ設定にはしません。

### 選択から採用への反映

ユーザーが選ぶ前に採用済みと記録しません。選択結果を採用判断の根拠にし、原画・通常姿・動作・作品の採用先へ適用するときは、登録・共通縮尺・QAを整合させます。比較ツール自体は既存の採用素材を書き換えません。採用前の候補や個人の選択記録を、公開用の素材一覧へ自動追加しません。

品質確認後におすすめ案を採用するようユーザーから委任された場合は、その指示と確認結果を採用根拠へ記録します。比較画面のクリックを代行したという履歴にはせず、指示に基づく管理上の選択と区別します。`catalogs/character-adoptions-v1.json` の `adoptions` に、対象ID・`status: adopted`・通常姿のパス/SHA/座標・短い演出の登録/SHA・非空の `selection_evidence` を明示します。既存の採用通常姿・全ポーズ・clipの同一性を検証してINDEXを再構築し、直前の `current/` を記録付きで保全してから共通ビューを再作成します。過去の通常姿やcollection、当時の画風QAは保全します。

## 台帳の更新と公開

管理担当は更新前の台帳・設定のSHA-256を読み、書き込み直前に同じ内容であることを確認します。別作業の更新があれば古いJSONを丸ごと書き戻さず、最新状態を読み直して差分を再適用します。共有台帳の更新は同時実行せず、排他的な担当予約と楽観的なハッシュ照合を併用します。

管理ツールは、設定の予約・解放と在庫公開に同じ設定ファイルのロックを使います。公開時は設定・在庫・人向け一覧のロックを保持して最終照合と置換を行い、その途中に予約だけが成功して古い在庫を完了扱いにすることを防ぎます。人向け一覧の固定公開先と親ディレクトリにはシンボリックリンクを使いません。生成中の範囲は保存先のパスで枝ごと除外し、その中の入力参照リンクも確定在庫へ取り込みません。

予約範囲の比較は大文字・小文字の違いも同じ領域として扱い、実パス解決やファイル情報の取得より前に除外します。

汎用ライブラリの `character_library.py refresh` も同じ予約設定のロックを使い、採用INDEXとファイル一覧の開始時SHA、原本の二重走査、書き込み直前の一致を確認します。ポーズ名・登録ID・画像パス・シートIDも照合し、画像のハッシュが正しくても別の動作名で選ばれる対応は拒否します。

画像と来歴を先に確定し、登録情報、collectionのmanifest、採用先、ファイル一覧の順で整合を確かめます。個々のJSONは一時ファイルを同じファイルシステム内へ書いて置換し、中途半端なJSONを読者へ見せません。複数ファイル全体が一度に更新できると仮定せず、更新中の記録と完了時のハッシュを残します。途中失敗を完了扱いにせず、直前の採用先を保って同じバッチから復旧します。

収録だけでは `active_production_set_ids`、作品の動作入力、通常姿、汎用ポーズの選択を変更しません。新しい共有素材は明示的な名前空間やセットIDから利用します。`expanded/` と `eyecatch/`、作品用の `prime-*`／`fibonacci-*` は別の用途として管理します。汎用ローダーへ未登録であっても、作品側から採用されている素材を未採用と決め付けません。

採用範囲を更新するときは、選択した登録情報・SHA-256・検査範囲・参照元・作品の根拠を記載します。静止画確認だけで動作確認済みにしません。新しい汎用素材の追加だけで既存ポーズのパスや共通基準高を変えません。

## 不整合・重複・中断時の整理

- 未登録画像を見つけたら、まず生成バッチ、来歴、作品からの参照を調べます。用途が確定しないものは未分類または候補として登録し、最大版数や更新時刻で採用しません。
- 書き込み中に画像が増減したり、読み取り前後でハッシュが変わったりした場合は、その在庫検査を失敗または保留として扱います。生成担当の完了後に再検査し、不安定な一回の観測で完全な在庫と記録しません。
- 既存ファイルのハッシュ不一致を見つけたら、実体・元シート・切り出し・来歴を調べます。検証を通す目的で期待ハッシュを現物へ置き換えません。新規追加が原因で一覧が古い場合は、追加内容を分類してから管理用一覧を再構築します。
- 同一SHA-256の重複は、同じ内容の別名として記録できます。来歴や参照元が異なることもあるため、勝手に削除・置換・リンク化しません。
- 中断した作業の予約は、日時だけで期限切れと決めません。所有者・実行状態・保存中のファイルを確認し、引き継ぐ担当と記録を残してから解除します。
- 不採用案は理由と来歴を付けて保管します。参照されていないと確認できていない原本や、制作中の素材を容量削減の対象にしません。

この仕様は追加のユーザー承認手順を設けません。依頼された管理・分類・検査と、明示的に依頼された採用変更を、それぞれの範囲で進めます。

## 管理コマンドと引き継ぎ

リポジトリのルートで実行します。本PCは `.venv/bin/python` を使い、別環境では準備済みのPythonへ読み替えます。読み取り確認は次のとおりです。

```bash
.venv/bin/python tools/manage_character_assets.py inspect
.venv/bin/python tools/manage_character_assets.py check
.venv/bin/python tools/character_library.py verify
```

新規生成の予約・解放は、衝突しない保存先と所有者を指定します。

```bash
.venv/bin/python tools/manage_character_assets.py reserve --batch-root assets/library/characters/kangaroo/generation-batches/task-a-f83c --owner ai-a --id task-a-f83c
.venv/bin/python tools/manage_character_assets.py release --reservation-id task-a-f83c --owner ai-a
```

予約の重なりを別所有者で確保することや、別所有者名による解放は拒否します。生成中の範囲は在庫の確定ハッシュ計算から除外し、`pending` として残します。既に採用・在庫登録されたファイルを予約で隠して、ハッシュ確認を免除しません。

管理担当は未分類の来歴・参照・品質を確かめて設定へ追記し、完了した範囲の管理在庫を再構築します。`refresh` は画像を移動せず、管理在庫とそこから作る人向け一覧を更新します。読み取った直前の在庫SHA-256を `--expected-registry-sha256` へ指定すると、その状態を前提とする更新を明示できます。

```bash
.venv/bin/python tools/manage_character_assets.py refresh --expected-registry-sha256 HASH_FROM_LAST_READ
.venv/bin/python tools/manage_character_assets.py check
```

汎用ライブラリのファイル一覧が追加素材により古くなった場合は、管理で分類・来歴・安定した実体を確認した後、管理担当だけが `tools/character_library.py refresh` を実行して `verify` します。生成中の未完了バッチは完了した素材と分けて扱います。既に登録されたファイルの変更は新規追加と区別して原因を調べます。

## 管理記録と再検査

現在の担当・分類・品質は管理設定と管理一覧を参照します。初回整理、作品ごとの引き継ぎ、独立再検査、旧出力から保全先への対応は、[管理記録の入口](../assets/library/collections/character-management/v001/manifest.json)へまとめています。過去の記録の日時と検査範囲を保ち、個別作業の経過を本仕様へ重複記載しません。

画風の自動測定を再実行する際は、`tools/audit_character_style.py --output <未使用の診断出力先>` を明示します。保全済みの監査先を新しい出力先として使いません。
