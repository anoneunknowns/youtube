# 枠内要素の配置意図と中央揃えの受入仕様

枠内の文字・数値・画像・図形は、**水平と垂直の配置意図を別々に指定し、描画後にその意図と一致することを確認する**。座標の指定だけで検査済みにしない。

設計する基準、実画から抽出する特徴、許容差、検査結果の順に記録する。素材の身体基準・支点の意味は [画像管理仕様](IMAGE-ASSET-MANAGEMENT.md#身体基準と支点)、完成作品の受入範囲は [制作仕様](PRODUCTION.md#完成mp4の検査と登録) を参照する。

## 配置意図の指定

設計時に枠／コンポーネントIDと、水平（左・中央・右）、垂直（上・中央・下・ベースライン等）の意図を記録する。

| 意図 | 水平 | 垂直 | 確認する位置 |
|---|---|---|---|
| 上下左右中央 | `center` | `center` | 実描画の両中心 |
| 枠の上部中央 | `center` | `top` | 左右の中心と、上端からの指定余白 |
| 左揃えで上下中央 | `left` | `center` | 左端からの指定余白と、上下の中心 |

## 対象と基準領域

- 枠線を除いた内側とpaddingから、有効領域 `content_box = [left, top, right, bottom]` を定義する。座標は出力画像のpx、右端・下端は含まない。
- 通常は対称paddingを使う。非対称paddingや光学的な補正を意図する場合は、その領域・補正理由を設計に明記する。検査後に基準領域をずらして合格にしない。
- 足支点への接地、行のベースライン、左揃え等を意図した部品へ、無条件に中央揃えを適用しない。複数行やラベル＋数値を一つのコンポーネントとした場合はグループ全体を測り、内部の行揃えやベースラインも別に確認する。

### 登録支点と観測する特徴点

足の接触点へ配置する場合、登録した解剖上の支点と、観測用の足元の帯の外接矩形中央は別の量である。両足の実接触領域を基準にした支点でも、その上側の輪郭を含めると帯の中央は変わり得る。

測定する特徴点が登録支点と一致しない場合は、元画像での相対位置を残して同じ変換で射影し、描画後の対応する特徴点と比較する。観測上の中央へ支点を変更して合格にしない。仮想地面を持つ空中画像も、描かれた足と地面との距離を保持する。

## 測定の共通条件

実描画の前景の可視範囲 `visible_box` と `content_box` を同一の座標系で測る。文字はフォントの行高・advance・描画原点ではなく、表示された字形全体の範囲を使う。画像は透明な余白込みのキャンバス寸法を可視範囲にしない。背景、親の枠線、影、対象外の装飾を測定へ混ぜない。

配置の種類を問わず、次を満たすこと。

1. 対象の可視範囲を検出でき、矩形と座標が有限・非空である。
2. コンポーネント全体が有効領域内に収まり、文字や画像が切れていない。中心一致だけでは、はみ出しを合格にしない。
3. 測定用の前景レイヤー／マスクには対象全体と周囲の余白があり、測定領域の端に対象が接していない。既に切れたROIだけで位置を測らない。

意図した位置からのずれには、次の既定の許容差を各軸へ独立に適用する。使用した閾値・抽出方法を記録し、許容差を拡大して位置ずれを隠さない。

| 測定対象 | 各軸の許容差 | 考慮する差 |
|---|---|---|
| 原寸の描画レイヤー（SOURCE） | 0.5px以内 | 整数pxへの丸め |
| 完成MP4の原寸デコード画像（FINAL） | 1px以内 | 量子化・前景抽出差 |

上寄せ等では、実描画の端と指定辺・paddingとのずれを測る。ベースラインを意図する場合は、基準線との整列と字形全体の収まりを確認する。

## 上下左右中央の判定

```text
target_x = (content_left + content_right) / 2
target_y = (content_top  + content_bottom) / 2
actual_x = (visible_left + visible_right) / 2
actual_y = (visible_top  + visible_bottom) / 2
dx = actual_x - target_x
dy = actual_y - target_y
```

共通条件に加え、`abs(dx) <= tolerance_px` と `abs(dy) <= tolerance_px` がそれぞれ成立した場合だけ合格とする。片方の軸だけの一致を合格にせず、符号付き差の合計・平均で相殺しない。

## 完成映像の前景抽出と誤検出の切り分け

完成映像のRGBフレームは、色・alpha推定・連結成分などから対象の前景を独立に抽出して測る。ROIを使う場合は `origin_xy` で出力画像上の座標へ戻す。描画関数が返した予定座標の再比較では、実描画の検査を代用できない。

### 同じ特徴を比較する

RGBAのアルファで抽出した外周と、合成後RGBの濃い線や色の芯は、同じ範囲とは限らない。圧縮前の合成RGBとデコードRGBへ同じ抽出を適用するなど、比較する実描画の特徴を対応付ける。アルファ閾値、背景色、抽出条件、画素比、描画・縮小倍率、出力画像上のpxへの換算を記録する。

ある表示倍率や観測器での成功は、別倍率・別背景・別観測器の成功を保証しない。高倍率の診断表示で失敗した場合も、その結果を保ち、確認済みの原寸表示や別の検査と範囲を分ける。表示校正のための微小移動と、元画像・登録・配置意図の修正を混同しない。

### ROIと他要素の混入

余白付きROIが近接する他要素を拾った場合は、実際の重なり・切れと、抽出時の混入を分けて確認する。対象の字形全体と周辺を含む原寸デコードフレーム、抽出前後のマスク、成分の分類根拠を残す。期待字形のステンシルを実画素の抽出範囲に使ったり、ROIを狭めて混入とともに対象の一部を切り捨てたりして、合格にしない。

フィルタは対象の役割（role）、場面・表示サイズ、適用条件を明示する。色・面積等の閾値には、実フレーム上の対象と除外成分を区別できる根拠を残す。対象字形のアンチエイリアス縁を保持し、小さい独立字形・点・句読点・下付字形を面積だけで消さない。別の役割や縮小表示へ適用する場合は、対象を失わないことを改めて確認する。

### 観測器の訂正と対照検査

近接要素の混入に対する抽出フィルタだけを修正する場合は、元の全ROI、`content_box`、両軸の許容差、字形の形状一致閾値を維持する。観測ROI・分類・校正自体に誤りがある場合は、原因・変更理由・新旧の測定条件を別記録へ残し、対象全体を保持できることと、検出すべき不良を拒否できることを独立に検証する。設計上の配置意図・有効領域や軸別の受入許容差を、観測器の誤りと混同して変更しない。

対照検査には元フレームの正例に加え、同じ実フレームの同じ復元パッチで、0px移動の正例と、許容差を超える水平・垂直それぞれの正負方向のずれ、切れ、空、誤値、誤色の負例を用意する。調べる条件だけを変え、正例が通り、各負例を拒否できることを確認してから、修正版で完成MP4を新規デコード・再観測する。

未合格の観測器、初回・中間診断、原寸画像・マスクは保全し、修正版の観測器と再観測結果を別の検査記録として保存する。MP4・観測器・対照入力のパスとハッシュ、適用範囲、閾値の根拠を結び付ける。案件固有のROI余白、成分面積、形状一致閾値、対照数を共通の受入値にはしない。

適用例は等差数列の再観測集計（制作原本の参考資料・公開版には未同梱: `output/arithmetic-sequence-counting-001-v001/arm-motion-review-20261113-v001/content/final-v003/content-final-summary.json`）、実フレームの対照検査（制作原本の参考資料・公開版には未同梱: `output/arithmetic-sequence-counting-001-v001/arm-motion-review-20261113-v001/content/final-v003/alignment-controls/verification.json`）、レビュー記録（制作原本の参考資料・公開版には未同梱: `design/arithmetic-sequence-counting-v1/arm-motion-review-20261113-v001/content/content-final-review-v003.txt`）を参照する。

## 検査を行う場面と記録

モックアップ、代表フレーム、完成映像で確認する。最短・最長の文言、最小・最大桁数、桁上がり、表示モード、複数行、フォントサイズ違い、表示サイズ変更を含める。アニメーションやフェードは入口・途中・出口を確認する。全状態を調べられる固定レイアウトは全状態で確認する。

検査記録には次を残す。

- 枠／コンポーネントID、場面・値・時刻、解像度、水平・垂直それぞれの配置意図。
- `content_box`、実測の `visible_box`、軸別の目標位置・ずれ・許容差。中央揃えでは両中心と `dx`・`dy`、上寄せ等では指定辺からの実測余白。
- はみ出し・切れの有無、軸別と総合の合否、原寸確認画像。数値判定に加え、原寸で上下・左右の余白も確認する。
- 対象ファイル・入力・観測コードのSHA、抽出条件、画素比・表示倍率、検査した状態と今回の実施件数。過去の結果や別条件の成功を今回の検査へ転記しない。

## 共通検査と回帰テスト

[`tools/component_alignment.py`](../tools/component_alignment.py) は上下左右中央の測定専用で、位置の自動修正や原画の変更を行わない。上寄せやベースライン揃えには無条件に適用しない。

```python
from tools.component_alignment import raster_centering_report

# component_layer: 対象だけを描いたRGBA、または前景を抽出したL/1マスク。
# 枠・背景を含めず、対象の周囲に測定用の余白を残す。
report = raster_centering_report(
    component_layer, content_box=(20, 10, 120, 90),
    name="number-card/label", tolerance_px=0.5,
)
assert report["passed"], report
```

[`tests/test_component_alignment.py`](../tests/test_component_alignment.py) は、片軸だけ一致、逆方向のずれの相殺、中心一致でも枠外、非対称padding、半pxの丸め、ROI原点、複数行、透明余白、空の対象、測定端の切れを回帰検査する。

```powershell
python -m unittest discover -s tests -p test_component_alignment.py
```

既存作品の過去の検査記録は、その時点の検査範囲として保持する。この共通テストの合格だけで、既存全動画の配置を再検査したとは記録しない。新作・レイアウト変更時に対象シーンを上記条件で検査する。
